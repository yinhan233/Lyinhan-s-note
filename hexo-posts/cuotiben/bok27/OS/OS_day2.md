**题目内容**：关于处理器状态以及用户态程序进入内核态的机制，下列说法正确的是（ ）。

**选项**：

- A. 用户程序可以直接修改 PSW 中的特权位，从而主动由用户态进入内核态
- B. 用户程序执行系统调用时，可通过陷入（trap）机制使处理器进入内核态，并转去执行相应的系统调用服务程序
- C. 用户程序执行普通变量赋值操作时，需要先进入内核态，然后由操作系统完成赋值
- D. 编译器会将用户程序中的普通函数调用自动转换为特权指令，从而使处理器进入内核态

## 3. 正确答案与解析

**正确答案**：**B**

**题目解析**：

逐项分析：

- **A 错**：PSW 中的特权位（模式位）决定 CPU 当前处于用户态还是内核态，用户程序**无权直接修改**；若允许用户程序随意修改，保护机制就失效了。
- **B 对**：系统调用是用户程序请求操作系统服务的入口。用户程序执行陷入指令（trap / 访管指令）后，CPU 由用户态切换到内核态，并根据系统调用号转去执行相应的服务程序。
- **C 错**：普通变量赋值是用户态即可执行的普通指令，不需要进入内核态，也不由操作系统代为完成。
- **D 错**：编译器只负责把普通函数调用编译成调用指令，**不会**把普通函数调用自动转换为特权指令。系统调用通常由库函数封装，库函数内部执行陷入指令完成状态切换。

故选 B。

**精修说明**：原笔记“例如 `read()` 等库函数确实会调用特权指令，但是由编译器调用转换”表述有误。`read()` 是库函数封装，内部执行的是**陷入指令**（trap / `syscall`），而陷入指令本身**不是特权指令**；编译器也不会把普通函数调用“转换”为特权指令。

**解题关键**：

> 用户程序主动请求操作系统服务的标准入口是**陷入（trap）**：用户程序执行陷入指令，硬件完成模式切换。用户程序不能直接改 PSW，也不能执行特权指令。

## 4. 知识点补充

<span style="display:inline-block;padding:1px 8px;border:1px solid rgba(127,127,127,.35);border-radius:999px;background:rgba(127,127,127,.08);font-size:12px;line-height:20px">deepseek/deepseek-v4-flash 精修于 2026-11-09 16:25</span>

### 4.1 用户态与内核态

| 项目 | 用户态 | 内核态 |
| :---: | :--- | :--- |
| 别名 | 目态 | 管态、核心态 |
| 可执行指令 | 普通指令 | 普通指令 + 特权指令 |
| PSW 模式位 | 用户态标识 | 内核态标识 |
| 访问资源 | 受限 | 可访问全部资源 |

- **特权指令**：只能在内核态执行的指令，如修改 PSW、开关中断、I/O 指令、设置时钟、清内存等。
- **非特权指令**：用户态和内核态都能执行，如普通算术运算、逻辑运算、访存（受地址保护约束）等。

### 4.2 系统调用的执行过程

1. 用户程序调用库函数（如 `read()`），准备系统调用号和参数。
2. 库函数执行**陷入指令**（trap / `syscall` / `int`）。
3. 硬件保存现场，将 PSW 模式位切换为内核态，跳转到内核固定的入口地址。
4. 内核根据系统调用号查表，执行相应的系统调用服务程序。
5. 服务完成后恢复现场，返回用户态，继续执行用户程序。

> 关键点：**陷入指令在用户态执行**，它本身不是特权指令；真正完成“用户态 → 内核态”切换的是硬件对陷入的处理。

### 4.3 易混淆概念

> **陷入指令 vs 特权指令**：陷入指令（trap、访管指令）可以由用户程序在用户态执行，执行后**主动**进入内核态；特权指令不允许在用户态执行。二者方向相反，不能混为一谈。

> **库函数 vs 系统调用**：`read()`、`write()` 等是库函数，内部封装了系统调用；`strlen()` 等纯计算库函数不会进入内核。不能因为“调用了库函数”就认为一定发生状态切换。

> **用户程序不能直接修改 PSW**：模式位的修改由硬件在陷入/中断/异常处理时完成，用户程序只能通过陷入指令“请求”切换，不能直接写 PSW。

> **编译器不会自动生成特权指令**：普通函数调用仍然是普通调用；系统调用是程序员（或库）显式使用系统调用接口的结果，不是编译器擅自“升级”为特权指令。

> **中断 vs 异常 vs 陷入**：陷入是异常的一种，由**当前指令**主动引发（如系统调用）；外中断由外部设备异步引发；故障、终止等异常由指令执行过程中的错误引发。三者都会让 CPU 进入内核态，但来源不同。
