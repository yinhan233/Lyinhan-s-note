## 一、本章核心内容概述

本章主要介绍 RISC-V 处理器的基础指令集，重点讲解指令的编码方式、功能、执行过程，以及如何利用这些指令完成数据处理、内存访问和程序控制。

全文最核心的观点是：CPU 执行程序，本质上就是不断地从内存获取指令，通过寄存器进行计算、访问内存，并根据执行结果决定下一条指令的位置。

理解 RISC-V，可以抓住四个关键问题：

1. 指令如何表示？——指令编码格式。
    
2. 数据如何处理？——加载、存储、算术、逻辑和移位指令。
    
3. 程序如何控制执行顺序？——PC 相对寻址、条件分支和跳转指令。
    
4. 处理器如何进行系统级操作？——CSR 寄存器及相关指令。
    

本章还通过汇编实例、反汇编分析和实验，说明这些指令在实际程序中的应用。

## 二、RISC-V 基础知识

对应原文 3.1 节，教材第44～45页

### 1. 什么是 RISC-V？

RISC-V 是一种基于精简指令集（RISC）设计思想的指令集架构（ISA）。

它采用模块化设计，主要特点包括：

- 精简性：基础指令集较小，便于处理器实现。
    
- 模块化：在基础指令集上，按需增加不同功能的扩展。
    
- 可扩展性：支持不同位宽和功能需求的处理器。
    
- 加载—存储架构：主要通过寄存器完成计算，使用专门的指令访问内存。
    

例如，文中使用 `/proc/cpuinfo` 查看平台支持的指令扩展：

`rv64imafdcsu`

其中，RV64 表示64位架构，常见扩展包括：

|扩展|含义|
|---|---|
|I|基础整数指令集|
|M|整数乘除法|
|A|原子操作|
|F|单精度浮点数|
|D|双精度浮点数|
|C|压缩指令|
|S|特权模式相关支持|
|U|用户模式相关支持|

这里要理解：RISC-V 并不要求所有处理器都实现相同的扩展，可以根据需要进行组合。

### 2. 为什么 RV64 是64位架构，指令却通常只有32位？

这是两个不同概念：

- 64位：表示该架构的通用寄存器和数据处理宽度等特征。
    
- 32位指令：表示一条普通基础指令的编码长度。
    

RISC-V 提供32个通用整数寄存器，编号为 `x0～x31`。选择一个寄存器只需要5个二进制位：

\[ 2^5=32 \]

因此，普通指令可以在32位编码中容纳寄存器编号、操作码、立即数等信息。

注意：本章主要讨论32位基础指令；RISC-V 还支持16位压缩指令。

## 三、RISC-V 六种指令编码格式

对应原文 3.2 节，教材第45～46页，重点参考图3.1

### 1. 六种编码格式

RISC-V 的基础指令根据功能，主要采用六种格式：

|格式|主要用途|代表指令|
|---|---|---|
|R 型|寄存器与寄存器运算|`add`、`sub`|
|I 型|立即数运算、加载等|`addi`、`lw`|
|S 型|将数据存入内存|`sw`、`sd`|
|B 型|条件分支跳转|`beq`、`bne`|
|U 型|高位立即数操作|`lui`、`auipc`|
|J 型|无条件跳转|`jal`|

记忆方法：

- R：寄存器运算
    
- I：立即数运算或加载
    
- S：存储数据
    
- B：条件分支
    
- U：高位立即数
    
- J：跳转
    

### 2. 指令编码的共同字段

虽然六种格式不同，但它们都围绕几个重要字段展开。

|字段|作用|
|---|---|
|`opcode`|操作码，区分指令类别|
|`funct3`|进一步区分具体操作|
|`funct7`|进一步区分具体操作|
|`rd`|目标寄存器，保存结果|
|`rs1`|第一个源寄存器|
|`rs2`|第二个源寄存器|
|`imm`|立即数，即编码在指令中的数值|

例如：

```
add t0, t1, t2
```

含义：

\[ t0=t1+t2 \]

其中：

- `t0` 是目标寄存器 `rd`
    
- `t1` 是源寄存器 `rs1`
    
- `t2` 是源寄存器 `rs2`
    

再例如：

```
addi t0, t1, 10
```

含义：

\[ t0=t1+10 \]

这次第二个操作数不再来自寄存器，而是指令中的立即数 `10`。

### 3. 什么是立即数？

立即数就是直接写在指令中的常数。

例如：

```
addi a0, a0, 5
```

表示：

\[ a0=a0+5 \]

不需要先从内存读取数字5。

立即数具有固定位宽，因此它的取值范围受到限制。

以12位有符号立即数为例：

\[ -2^{11}\le imm\le2^{11}-1 \]

即：

\[ \boxed{-2048\le imm\le2047} \]

这也是后面加载、存储和部分算术指令需要注意的限制。

### 4. 零扩展与符号扩展

当一个较短的数据放入较宽的寄存器时，需要扩展位数。

零扩展（Zero Extension）：高位全部补0，适用于无符号数据。

符号扩展（Sign Extension）：高位填充原数据的符号位，保留有符号数的数值含义。

例如，将8位二进制数 `10001010` 扩展到16位：

同一组8位数据，两种扩展方式

零扩展

00000000

10001010

符号扩展（原数据最高位为1）

11111111

10001010

左半部分是扩展产生的高8位，右半部分是原始数据。

这两个结果虽然低8位相同，但作为16位整数解释时，数值不同。

## 四、加载与存储指令

对应原文 3.3 节，教材第46～48页

这是理解 RISC-V 工作方式的重要内容。

### 1. 核心思想：加载—计算—存储

RISC-V 采用加载—存储架构，通常不能直接对内存中的数据执行普通算术运算。

基本过程是：

内存（Memory）

保存待处理的数据

Load：加载

寄存器（Register）

进行算术、逻辑和其他运算

Store：存储

内存（Memory）

保存运算结果

例如：

```
lw   t0, 0(a0)     # 从内存读取32位数据
addi t0, t0, 1     # 数据加1
sw   t0, 0(a0)     # 将结果写回内存
```

这三条指令完成了：读取一个数、加1、写回原位置。

### 2. 加载指令（Load）

加载指令用于把内存数据读取到寄存器。

常见指令如下：

|指令|读取宽度|扩展方式|
|---|---|---|
|`lb`|8位|符号扩展|
|`lbu`|8位|零扩展|
|`lh`|16位|符号扩展|
|`lhu`|16位|零扩展|
|`lw`|32位|符号扩展|
|`lwu`|32位|零扩展|
|`ld`|64位|直接读取64位|

基本格式：

```
lw rd, offset(rs1)
```

有效内存地址的计算公式为：

\[ \boxed{\text{有效地址}=rs1+\text{sign\_extend}(offset)} \]

例如：

```
lw t0, 8(a0)
```

假设：

```
a0 = 0x80000000
```

那么实际读取地址就是：

```
0x80000000 + 8
= 0x80000008
```

指令会读取该地址开始的4个字节，并将经过符号扩展的结果存入 `t0`。

注意，括号表示以寄存器中的值作为地址，并不是普通数学运算的括号。

### 3. 存储指令（Store）

存储指令将寄存器中的数据写入内存。

|指令|写入宽度|
|---|---|
|`sb`|8位（1字节）|
|`sh`|16位（2字节）|
|`sw`|32位（4字节）|
|`sd`|64位（8字节）|

例如：

```
sw t0, 8(a0)
```

表示：把 `t0` 的低32位存入以 `a0+8` 为起始地址的内存区域。

加载和存储都采用基址加偏移量寻址，文中的这两类基本指令使用12位有符号偏移量，范围为 `-2048～2047` 字节。

### 4. LUI：构造较大的立即数

由于普通立即数只有有限的位数，如果需要构造较大的常数，可以使用：

```
lui rd, imm
```

其基本作用是将20位立即数放在结果的高20位位置，低12位补0；在RV64中，再按32位结果进行符号扩展。

例如：

```
lui t0, 0x80200
```

在RV64中得到：

```
t0 = 0xFFFFFFFF80200000
```

注意：`lui` 虽然含有 Load 一词，但它不从内存加载数据，而是将立即数写入寄存器。

## 五、PC 相对寻址

对应原文 3.4 节，教材第49～52页

### 1. 什么是 PC？

PC（Program Counter，程序计数器）用于保存当前要执行的指令地址。

正常情况下，CPU 按顺序执行指令；遇到跳转、分支时，PC 会改变，使程序转向其他位置执行。

PC 相对寻址，就是利用当前指令的 PC 值加上偏移量，计算目标地址。

### 2. AUIPC 与 LUI 的区别

这是本章非常重要的一组指令。

|指令|作用|
|---|---|
|`lui rd, imm`|将立即数左移12位并符号扩展，不加PC|
|`auipc rd, imm`|将立即数左移12位并符号扩展，再加当前PC|

例如，假设当前 PC 为 `0x80200000`：

```
auipc a5, 0x2
lui   a6, 0x2
```

执行结果：

```
a5 = 0x80202000
a6 = 0x00002000
```

区别在于：

- AUIPC 计算时使用当前 PC。
    
- LUI 不使用 PC。
    

### 3. 为什么 AUIPC 经常与 ADDI 配合？

`auipc` 产生的偏移量低12位为0，因此通常配合 `addi` 完成更精细的地址计算。

```
auipc a0, 2
addi  a1, a0, -2048
```

假设第一条指令的 PC 是 `0x80200000`：

```
auipc 执行后：
a0 = 0x80202000

addi 执行后：
a1 = 0x80201800
```

这样就构造出了目标地址 `0x80201800`。

关键知识点：低12位立即数是有符号数，计算高20位时需要考虑符号带来的进位调整。

教材给出的计算方法为：

```
hi20 = (offset >> 12) + offset[11]
lo12 = offset & 0xfff
```

这里的 `lo12` 要按12位有符号数解释。

### 4. 什么是 PIC？

PIC（Position Independent Code）即位置无关代码。

它的主要意义是：程序或共享库被加载到不同的内存位置时，仍然可以通过相对寻址正确访问数据和代码。

本节还介绍了 `la`、`lla`、`li` 等伪指令，以及 GOT（全局偏移表）。

伪指令并不一定对应单条机器指令，而是由汇编器展开为一条或多条实际指令。

## 六、移位、位操作与算术指令

对应原文 3.5～3.7 节，教材第53～57页

### 1. 移位指令

RISC-V 主要支持三种移位操作：

|指令|名称|特点|
|---|---|---|
|`sll`|逻辑左移|左移，低位补0|
|`srl`|逻辑右移|右移，高位补0|
|`sra`|算术右移|右移，高位补符号位|

对应的立即数版本分别是：

`SLLI`、`SRLI`、`SRAI`。

例如：

```
slli t0, t1, 2
```

表示将 `t1` 的值左移2位，保存到 `t0`。

最容易混淆的是逻辑右移和算术右移。

- 逻辑右移：不考虑符号，最高位补0。
    
- 算术右移：考虑符号，最高位复制原符号位。
    

另外，RV64中带 `w` 后缀的指令，如 `sllw`、`srlw`、`sraw`，只对低32位进行操作，并把32位结果符号扩展为64位。

### 2. 位操作指令

主要有三类：

|指令|操作|常见作用|
|---|---|---|
|`and`|按位与|提取或清除特定位|
|`or`|按位或|将特定位设为1|
|`xor`|按位异或|翻转位、比较差异|

各自还有立即数版本：

```
andi
ori
xori
```

教材重点介绍了异或运算的三个性质：

\[ a\oplus0=a \]

\[ a\oplus a=0 \]

\[ a\oplus1=\neg a \]

其中，最后一个式子表示单个位的取反。

例如：

```
xor t0, t0, t0
```

执行之后：

```
t0 = 0
```

这是利用相同数异或结果为0的性质。

此外，`not` 是伪指令，可以使用与 `-1` 异或的方式实现按位取反。

### 3. 算术指令

本章主要介绍整数加减法：

|指令|功能|
|---|---|
|`add`|两个寄存器相加|
|`addi`|寄存器加立即数|
|`sub`|两个寄存器相减|
|`addw`|低32位加法|
|`addiw`|低32位立即数加法|
|`subw`|低32位减法|

例如：

```
add  t0, t1, t2
addi t0, t0, 5
sub  t0, t0, t2
```

教材特别强调：

RV64 中普通算术指令与带 `w` 后缀的算术指令，处理的数据宽度不同。

普通 `add` 使用64位操作数，而 `addw` 只计算低32位，并将结果符号扩展为64位。

所以，`add` 和 `addw` 即使使用相同的寄存器，也可能产生不同结果。

## 七、比较指令与程序控制

对应原文 3.8～3.10 节，教材第57～61页

这部分回答一个重要问题：CPU 如何执行 C 语言中的 if、else、while，以及函数调用？

### 1. 比较指令

常见的比较指令：

|指令|含义|
|---|---|
|`slt`|有符号小于比较|
|`sltu`|无符号小于比较|
|`slti`|有符号数与立即数比较|
|`sltiu`|无符号比较（立即数字段仍为有符号扩展）|

例如：

```
slt t0, t1, t2
```

如果 `t1 < t2`，那么：

```
t0 = 1
```

否则：

```
t0 = 0
```

教材还介绍了 `seqz`、`snez`、`sltz`、`sgtz` 等比较伪指令。

### 2. 无条件跳转

主要指令有两条：

JAL（Jump And Link）

```
jal ra, label
```

完成两个动作：

- 跳转到 `label` 指定的地址。
    
- 将返回地址保存到 `ra` 寄存器。
    

JAL 的直接跳转范围约为当前PC的 ±1 MiB。

JALR（Jump And Link Register）

```
jalr ra, 0(t0)
```

它根据寄存器值及偏移量确定跳转目标，同时保存返回地址。教材重点说明其12位有符号偏移量。

JAL 和 JALR 是实现函数调用与返回的重要基础。

### 3. 条件跳转

常用条件跳转指令：

|指令|跳转条件|
|---|---|
|`beq`|两个寄存器相等|
|`bne`|两个寄存器不相等|
|`blt`|有符号小于|
|`bge`|有符号大于等于|
|`bltu`|无符号小于|
|`bgeu`|无符号大于等于|

例如：

```
beq t0, t1, equal

addi a0, x0, 0
j end

equal:
addi a0, x0, 1

end:
```

这个例子实现了简单的条件判断：

- 若 `t0 == t1`，则 `a0 = 1`。
    
- 否则，`a0 = 0`。
    

条件分支采用 B 型编码，偏移量是2字节的倍数，其直接跳转范围约为当前PC的 ±4 KiB。

### 4. 三种寻址范围的区别

这是本章需要重点记忆的知识点。

|寻址方式|典型指令|范围|
|---|---|---|
|短距离条件跳转|`beq`、`bne`|约 ±4 KiB|
|直接无条件跳转|`jal`|约 ±1 MiB|
|组合长距离跳转|`auipc` + `jalr`|约 ±2 GiB|

教材指出，编译器和链接器可以通过指令组合与链接器松弛优化，实现对不同距离目标的访问。

## 八、CSR 指令：操作处理器系统寄存器

对应原文 3.11 节，教材第61～62页

CSR（Control and Status Register）即控制与状态寄存器。

普通寄存器主要负责保存计算数据；CSR 则用于管理或反映处理器的系统状态。

CSR 指令主要包括：

|指令|功能|
|---|---|
|`csrrw`|读取CSR旧值，并用新值替换|
|`csrrs`|读取CSR旧值，并设置指定的位|
|`csrrc`|读取CSR旧值，并清除指定的位|
|`csrrwi`|使用立即数执行读写|
|`csrrsi`|使用立即数设置位|
|`csrrci`|使用立即数清除位|

例如：

```
csrrw t0, sscratch, tp
```

该指令的核心过程是：

1. 读取 `sscratch` 原来的值，保存到 `t0`。
    
2. 将 `tp` 的值写入 `sscratch`。
    

相当于同时完成一次读取和一次写入。

教材还介绍了 `csrr`、`csrw`、`csrs`、`csrc` 等CSR伪指令。

## 九、重要陷阱：为什么 ret 后可能进入死循环？

对应原文 3.13 节，教材第62～64页

这是本章最有实践价值的案例之一。

### 1. 问题出现的原因

RISC-V 使用 `ra`（返回地址寄存器）记录函数的返回地址。

假设函数A调用函数B，函数B又调用函数C。

函数A

调用函数B

函数B

ra 原本保存返回A的地址

函数C

B调用C时，ra被改写为返回B的地址

C返回B后，如果B未恢复ra，B的ret就无法正确返回A

这是因为 `call` 通常会修改 `ra`，而 `ret` 又需要根据 `ra` 中的值确定返回位置。

如果B没有保存原来的返回地址，它就可能在执行 `ret` 时跳回函数B中的某个位置，甚至反复执行 `ret`，形成死循环。

### 2. 解决方法

核心原则：

当一个函数还需要调用其他函数时，必须妥善保存自己的返回地址。

常用方式是：

- 在调用其他函数之前，把 `ra` 保存到栈中。
    
- 被调用函数返回之后，从栈中恢复 `ra`。
    
- 最后执行 `ret` 返回上一级函数。
    

教材也展示了使用临时寄存器保存返回地址的方法，但通常使用栈更适合一般的函数调用场景。

实验主要基于 BenOS 环境，并要求利用 GDB 单步调试，查看寄存器和内存的变化，从而验证程序是否符合预期。

这些实验体现出本章的学习思路：先理解单条指令，再通过多条指令的组合实现完整功能。

## 十二、本章最终结论

虽然本章介绍了很多汇编指令，但它们可以归纳为三个基本能力：

第一，处理数据。 使用加载、存储、算术、逻辑和移位指令，完成数据读取、计算与保存。

第二，控制程序。 使用比较、条件分支和无条件跳转，完成判断、循环、函数调用及返回。

第三，管理运行状态。 利用PC相对寻址、CSR等机制，让程序能够访问目标地址并与处理器系统状态交互。

本章不仅要求理解每条指令的作用，更强调：

掌握指令编码、立即数范围、符号扩展、寄存器变化、PC变化和函数返回地址管理，才能真正看懂 RISC-V 汇编程序。

建议复习时按照以下顺序理解：

`指令编码 → 寄存器 → 内存访问 → 数据运算 → 比较与跳转 → 函数调用 → CSR → 实验调试`

这条主线基本贯穿整章，也是从认识单条指令走向阅读完整汇编程序的关键。
