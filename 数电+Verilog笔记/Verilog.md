## 📦 第一篇：Verilog HDL 基础语法与核心逻辑
### 1.1 Verilog 模块结构与设计思维
Verilog 不是在“写代码”，而是在“搭电路”。所有的电路都可以被封装为一个模块（Module），并通过端口与其他电路相连。
**模块的基本骨架 (The Module Template)**
任何一个可综合的基础模块都必须以 `module` 开始，以 `endmodule` 结束。
*   **组合逻辑电路**（无记忆功能，如加法器）：常用 `assign` 语句实现。
*   **时序逻辑电路**（有记忆功能，此时钟驱动，如计数器）：常用 `always @(posedge clk)` 实现。
> 💡 **教授批注：标准规范的演进 (1995 vs 2001)**
> *   **Verilog-1995 标准**：端口声明和数据类型定义是分开的（先写输入输出，再写类型），代码较冗长。
> *   **Verilog-2001 标准**：允许在端口列表中直接定义方向和数据类型（如 `input wire A`），**强烈推荐**在现代设计中使用 2001 标准，以减少低级错误。

**代码对比演示：**
```verilog
// 【旧版】Verilog-1995 标准
module AOI (A, B, C, D, F);
    input A, B, C, D;     // 端口声明
    output F;
    wire A, B, C, D, F;   // 类型声明
    assign F = ~((A&B) | ~(C&D));
endmodule

// 【推荐】Verilog-2001 标准
module AOI (
    input wire A, B, C, D, // 合并声明，极致清爽
    output wire F
);
    assign F = ~((A&B) | ~(C&D));
endmodule
```
### 1.2 Verilog 文字规则与 C 语言的异同
*   **空白符**：空格、Tab、换行在综合时被忽略，主要用于代码排版。
*   **注释**：与C语言完全一致。单行 `//`，多行 `/* ... */`。
*   **大小写敏感**：关键字（如 `module`, `wire`）**必须全部小写**。用户自定义变量区分大小写。
*   **语句结束**：除少数语句（如 `endmodule`）外，每个语句末尾必须有分号 `;`。
**⚡ 与 C 语言的致命区别：**
1.  **本质不同**：软件语言（C）是完全顺序执行的；硬件语言（Verilog）具有极强的**并行性**。
2.  **调试方式**：Verilog 不能使用单步调试、断点等软件思维。看似可实现的顺序代码，综合成电路后可能完全无法工作。
### 1.3 核心数据类型：常量、参数与变量
Verilog 包含4种基本的逻辑状态：`0`（低电平）、`1`（高电平）、`x/X`（未知状态）、`z/Z`（高阻态/悬空）。
#### (1) 常量 (Constants)
最常用的书写格式（基数格式）： **`[size]'base value`**
*   `size`：位宽（二进制长度）。
*   `'`：单引号（必填，分隔符）。
*   `base`：进制。`b` (二), `o` (八), `d` (十), `h` (十六)。
*   *特殊占位符*：`?` 字符可以代替 `z`。
> ⚠️ **避坑指南：位宽截断与补齐**
> *   **如果不定义位宽**（如 `'hAF`）：默认位宽通常取决于机器字长（至少32位）。
> *   **实际位宽 < 定义位宽（左侧补齐）**：如 `10'b10` 会在左边补0，变成 `0000000010`。如果最左侧是 `x` 或 `z`，则用 `x` 或 `z` 补位。
> *   **实际位宽 > 定义位宽（左侧截断）**：如 `3'b1001_0011` 会被截断为 `011`。
#### (2) 符号常量 (Parameters)
用于定义时延或变量的位宽，方便代码重用和修改。
```verilog
parameter sel = 8, code = 8'ha3;
```
#### (3) 变量 (Variables)
这是 Verilog 最核心的数据类型，分为两大阵营：**线网型 (Net)** 和 **寄存器型 (Register)**。
```verilog
wire [7:0] databus; // 线网型：定义了一个8位宽的总线，必须用 assign 驱动，自身无记忆
reg  [7:0] q;       // 寄存器型：8位宽的寄存器，只能在 always 或 initial 块中赋值，具有记忆性
```
### 1.4 存储器的建模与赋值
存储器在 Verilog 中是通过**寄存器数组**来声明的。
**语法公式：** `reg [数据位宽_msb : lsb] 存储器名称 [存储器深度_upper : lower];`
```verilog
reg [0:3] MyMem [0:63]; // 定义了 64个 容量，每个单元字长 4位
```
**如何赋值？**不能一条语句把整个数组赋满！
1.  **逐个单元单独赋值**：`MyMem[0] = 4'hA; MyMem[1] = 4'h8;`
2.  **系统任务批量读取**：`$readmemb("ram.patt", MyMem);`。
### 1.5 表达式与九大核心操作符
*建议在实际编程中大量使用圆括号 `()` 来明确优先级。*
### 算术操作符 (`+`, `-`, `*`, `/`, `%`)
只要出现一个未知数 `x` 或高阻 `z`，**整个算术运算的结果就是不确定数 `x`**。
### 相等操作符 (⭐⭐⭐ 重点区分)
- **逻辑相等** (\=\= \!\=)：只要比较的位中出现了 `x` 或 `z`，比较结果就是 `x`。
- **全等** (\=\=\=, \!\=\=)：要求两边完全一模一样（包括 `x` 和 `z`），匹配为 `1`，不匹配为 `0`，**绝不会输出 `x`**。
### 归约操作符
单目运算符，放在一个多位向量前，内部各位相互运算，最终“归约”成一个 **1 位的标量**。可用归约异或 `^` 检查数据中是否包含 `x`。
### 位拼接 `{}`
将多个信号合并为一个总线。如 `assign {cout, sum} = a + b + cin;`。
复制用法：`{3{1'b1}}` 等同于 `3'b111`。

## 📦 第二篇：行为级建模与时序/组合逻辑设计
### 2.1 Verilog 行为语句综合性总览
并非所有的Verilog代码都能转化为实际的硬件电路。请牢记下表：

| 类别 | 语句类型 | **是否可综合 (转化为实际电路)** |
| :--- | :--- | :---: |
| **过程语句** | `initial` / `always` | `initial` ❌ (仅仿真) / `always` ✅ |
| **赋值语句** | `assign` / `=`, `<=` | ✅ |
| **条件/循环** | `if-else`, `case`, `for` | ✅ (`for` 边界必须是常数) |
| **其他循环** | `repeat`, `while`, `forever`| ❌ (主要用于仿真) |

### 2.2 过程语句 (initial & always) 与敏感列表
在一个模块中，`initial` 和 `always` 语句的使用次数是不受限制的，且它们是**并发执行**的。
*   **`initial`**：仅执行一次，用于仿真波形生成。
*   **`always`**：不断重复执行。必须配合**触发条件（敏感信号）**使用。
```verilog
always @(<敏感信号表达式 event-expression>) begin
    // 过程赋值语句、条件选择、循环、task/function调用等
end
```
*   **组合逻辑触发**：`always @(*)` 或 `always @*`（**强烈推荐**：自动包含块内所有输入信号，防止遗漏）。
*   **时序逻辑边缘触发**：`always @(posedge clock)`（上升沿触发）或带异步复位 `always @(posedge clk or negedge reset)`。
### 2.3 ⭐ 赋值语句：阻塞 vs 非阻塞 (核心难点)
这是Verilog中最容易出错的考点。请用“电路连线”和“寄存器打拍”的思维来理解。
#### (I) 持续赋值语句 (`assign`)
目标必须是 `wire`，右侧变化**立刻**反映到左侧。用于简单**组合逻辑**。
#### (II) 过程赋值语句 (在 `always` 内部)
*   **阻塞赋值 (=)**：**顺序执行**。当前语句执行完才执行下一句，仿佛被“阻塞”。用于 **组合逻辑** 建模。
*   **非阻塞赋值 (<\=)**：**并发执行**。右侧值先计算保存，直到**整个块结束时**，才同时赋给左侧。用于 **时序逻辑** 建模。

> 🛡️ **硬件设计的 6 条黄金法则 (务必背诵)**
> 1. **组合逻辑**建模，在 `always` 中用 **阻塞赋值 (=)**。
> 2. **时序逻辑**建模，在 `always` 中用 **非阻塞赋值 (<\=)**。
> 3. **锁存器 (Latch)** 建模，尽量用 **非阻塞赋值 (<\=)**。
> 4. 同一个 `always` 块若既有组合有时序，**必须用非阻塞赋值 (<\=)**。
> 5. **绝对禁止混用！** 同一个块中不要将 \= 和 <\= 混杂使用。
> 6. **多驱动冲突：** 严禁在多个 `always` 块中对**同一个变量**赋值。
### 2.4 条件与循环语句及其在硬件中的应用
*   **`if-else`**：会综合出具有优先级的级联选择逻辑。
*   **`case`**：**只要匹配到一个分支并执行完毕后，就会自动跳出，不需要写 `break`！**（强烈建议加上 `default`，防止生成意外的 Latch 锁存器）。
**循环语句及其在硬件中的应用**
`for` 循环在综合时会被“展开 (Unroll)”，物理上相当于复制了多次相同的电路结构。利用 `for` 循环可以极大简化代码（例如实现多位投票表决器）。如果不使用 for，可能需要写出极其庞大的真值表逻辑。
💡 **实例源码：七人投票表决器 (超过4人赞成则通过)**
```verilog
module voter7(input[6:0] vote, output reg pass);
    reg[2:0] sum; // 内部计数器，最大需要记录7（二进制111，需要3位）
    integer i;    // 循环变量

    always @(vote) begin
        sum = 0; // 阻塞赋值，每次计算前清零
        for(i = 0; i <= 6; i = i + 1)
            if(vote[i]) sum = sum + 1; // 统计赞成票数
        
        if(sum >= 4) pass = 1;         // 大于等于4通过
        else         pass = 0;
    end
endmodule
```
### 2.5 综合实例解析：译码器与乘法器源码详解
💡 **实例 1源码：BCD码-七段数码管译码器 (共阴极)**
*   **原理：** 共阴极意味着输出 `1` 时对应的LED段点亮。由于是固定的真值表映射，使用 `always @(*)` 配合 `case` 语句是最佳选择。
```verilog
module decode4_7(
    input [3:0] indec,
    output reg [6:0] decodeout
);
    always @(*) begin // 或者 always @(indec)
        case(indec)
            4'd0: decodeout = 7'b1111110; // 显示 0 (只有g段为0)
            4'd1: decodeout = 7'b0110000; // 显示 1
            4'd2: decodeout = 7'b1101101; // 显示 2
            4'd3: decodeout = 7'b1111001; // 显示 3
            // ... (篇幅原因省略4-8，完全对应的查表法)
            4'd9: decodeout = 7'b1111011; // 显示 9
            default: decodeout = 7'b1111110; // 容错处理，默认显示0
        endcase
    end
endmodule
```
💡 **实例 2源码：8位二进制乘法器 (利用for循环实现移位与相加)**
展示了如同手工计算乘法一样的硬件算法：检查乘数的最低位，若为1则加上被乘数，随后乘数右移，被乘数左移，循环8次。
```verilog
module mult_repeat #(parameter size=8) (
    input [size:1] a, b,
    output reg [2*size:1] outcome
);
    reg [2*size:1] temp_a; // 扩展被乘数位宽以防溢出
    reg [size:1] temp_b;
    integer i;

    always @(a or b) begin
        outcome = 0; 
        temp_a = a; 
        temp_b = b;
        for (i = 1; i <= size; i = i + 1) begin
            if (temp_b[1]) // 判断乘数当前最低位是否为1
                outcome = outcome + temp_a; // 累加
        
            temp_a = temp_a << 1; // 被乘数左移一位
            temp_b = temp_b >> 1; // 乘数右移一位
        end
    end
endmodule
```

## 📦 第三篇：电路描述风格与子程序进阶

### 3.1 Verilog 子程序：任务 (Task) 与函数 (Function)
用于封装重复代码，提高复用性。

| 特性对比 | 任务 (Task) | 函数 (Function) |
| :--- | :--- | :--- |
| **适用场景** | 多输出、包含内部时序延迟的复杂逻辑 | 单一返回值、纯组合逻辑数学运算 |
| **返回值** | 无返回值 (通过 output/inout 传递) | 必须有返回值，输出变量由函数名担任 |
| **端口要求** | 定义首行无端口列表，可无输入 | 具有输入端口声明，**必须至少有1个输入** |
| **调用关系** | 可调用其他 Task 和 Function | 只能调用其他 Function，**不能调用 Task** |
| **耗时行为** | 可以包含延迟、时序控制 (`#`, `@`) | **不能**包含时间控制，必须瞬间执行完毕 |

💡 **实例源码：定义与调用 Task 实现 ALU 运算**
```verilog
module alu(code, a, b, c);
    input [1:0] code;
    input [3:0] a, b;
    output reg [4:0] c;

    // --- 任务定义开始 (注意：定义的第一行没有括号和端口列表) ---
    task my_and; 
        input [3:0] a, b;  // 紧接着在内部声明端口
        output [4:0] out;
        integer i;
        begin
            for (i=3; i>=0; i=i-1)
                out[i] = a[i] & b[i];
        end
    endtask
    // --- 任务定义结束 ---

    always @(code or a or b) begin
        case(code)
            2'b00: my_and(a, b, c); // 调用任务，注意端口顺序必须严格匹配
            2'b01: c = a | b;
            // ... 其他分支逻辑
        endcase
    end
endmodule
```
### 3.2 深入剖析并发与顺序执行
1.  **并发执行 (Concurrent)**：模块中的多个 `always`、`assign`、实例调用，在物理上是并行的，**书写先后顺序毫不影响执行结果**。
2.  **顺序执行 (Sequential)**：**唯独**在 `always` 或 `initial` 内部，如果是阻塞赋值 (\=)，则是按代码书写顺序执行的。
### 3.3 Verilog 描述电路的三大风格 (重点)
抽象级别越高，设计越容易。同一电路（如 2选1 多路选择器 MUX，逻辑表达式：`out = (a · ~sel) + (b · sel)`）可有三种绝然不同的写法：
1️⃣ **结构描述 (Structural) —— “搭积木”**
最底层的描述，直接调用 Verilog 内置的门元件。*格式*：`门名称 实例名 (输出, 输入1, 输入2...);` (注意永远是输出在前)。
```verilog
not (sel_n, sel);
and (a1, a, sel_n), (a2, b, sel);
or  (out, a1, a2);
```
2️⃣ **数据流描述 (Dataflow) —— “逻辑公式”**
使用 `assign` 持续赋值，只要等号右侧发生变化就立刻重新计算。适用于推导出了逻辑代数表达式的情况。
```verilog
// 方式一：直接映射布尔表达式
assign out = (a & (~sel)) | (b & sel); 

// 方式二：更优雅的条件运算符 (推荐极简写法)
assign out = sel ? b : a; 
```
3️⃣ **行为描述 (Behavioral) —— “高级编程思维”**
抽象度最高，只需关注“因果行为关系”，把挑选具体门电路的脏活交给综合软件。**这是工程中最常用的建模方式**。
```verilog
always @(a or b or sel) begin
    if (sel) out = b;
    else     out = a;
end 
// 注意：在 always 块中被赋值的 out 必须提前声明为 `reg` 类型
```
### 3.4 组合逻辑电路的 EDA 设计流 (交通灯监控案例)
**标准流程：** 逻辑抽象 $\rightarrow$ 列真值表 $\rightarrow$ 卡诺图化简得出布尔表达式 $\rightarrow$ Verilog HDL代码实现 $\rightarrow$ 综合与时序仿真 $\rightarrow$ 下载测试。
**任务需求：** 监视红(R)、黄(A)、绿(G)三个信号灯。正常情况下只能有一个灯亮（1表示亮）。出现故障（全灭，或亮两个及以上）输出报警 `Z=1`。
*通过卡诺图化简可得：`Z = R'A'G' + RA + RG + AG`*
在熟练掌握行为描述风格后，甚至可以跳过卡诺图化简，直接根据真值表写 `if` 逻辑，代码直观且极难出错：
```verilog
always @(R, A, G) begin
    // 判断正常的灯状态 (只有 001, 010, 100 三种情况正常)
    if ( ({R,A,G} == 3'b001) || ({R,A,G} == 3'b010) || ({R,A,G} == 3'b100) )
        Z = 0; // 正常
    else
        Z = 1; // 故障
end
```

## 📦 第四篇：常用中规模集成电路 (MSI) 与物理现象
### 4.1 常用组合逻辑：编码器 (Encoder) 深度剖析
将输入电平信号翻译成对应的二进制代码。
*   **普通编码器**：**绝对规则是任何时刻只允许输入一个有效信号！** 否则输出错误。
*   利用**无关项 (Don't Care, 'X')**：在包含多个变量的真值表中，那些“永远不会同时发生”的状态可用于极大地简化逻辑代数表达式。例如 8-3 编码器，化简后可直接写为数据流描述：`assign Y2 = I4 | I5 | I6 | I7;`。
### 4.2 优先编码器与译码器进阶 (含源码)
**优先编码器 (Priority Encoders)**
允许同时输入多个信号，电路只对**优先级最高**的信号编码。
*   **商用芯片实例 (74HC148 / 74HC147)**：这两款芯片均采用**低电平有效 (Active-Low)**，输入 `0` 表示有信号触发。带有 `$S'$` (选通输入), `$Y_S'$` (选通输出), `$Y_{EX}'$` (扩展输出) 用于多芯片级联。
*   **Verilog EDA 实现技巧**：代码中的 `if-else if-else` 结构天然具备从上到下的判定优先级，是编写优先编码器的最优解！
💡 **实例源码：74HC147 行为描述片段 (I9 优先级最高)**
```verilog
always @(I) begin
    // 低电平有效，因此使用 ~ 取反来判断是否有信号输入
    if(~I[9])      Y = 3'b0110;  // I9只要有输入，立刻截胡，不管后面的状态
    else if(~I[8]) Y = 3'b0111;  // 走到这一步，说明前面优先级更高的没触发
    // ... 依次类推 ...
    else if(~I[1]) Y = 3'b1110;
    else           Y = 3'b1111;  // 无有效输入时的默认状态
end
```
**译码器 (Decoders)**
编码的逆过程。特定输入只点亮多个输出中的1个。
*   **数码管显示译码器**：将BCD码映射为7段LED信号，分共阴极（高电平点亮）和共阳极（低电平点亮）。
💡 **实例源码：3-8 译码器**
使用 `case` 语句建模最佳，直观映射。
```verilog
always @(A) begin
    case (A)
        3'b000: Y = 8'b00000001; // 仅 Y0 有效
        3'b001: Y = 8'b00000010; // 仅 Y1 有效
        3'b010: Y = 8'b00000100; // 仅 Y2 有效
        // ...
        default: Y = 8'b10000000;
    endcase
end
```
### 4.3 数据选择器、加法器与数值比较器
*   **4选1 数据选择器 (MUX)**：拥有两个选择端 `S[1:0]`，从4个输入（C, D, E, F）中选出1个。使用 `case(S)` 语句最为清晰直观。
*   **加法器 (Adders)**：
    *   **半加器 vs 全加器**：半加器不考虑低位进位；全加器考虑低位进位。利用两个半加器和一个或门可拼接出一个全加器。
    *   **串行进位加法器**：多个全加器级联。缺点是**速度极慢**，存在高位死等低位结果的“涟漪”等待效应。
    *   **Verilog 极简实现**：无需手写门级结构，综合工具会自动推断出加法器：
    ```verilog
	    assign {cout, sum} = ina + inb + cin;
    ```
*   **数值比较器**：现代设计中直接使用 \>\= 等运算符即可，极其高效。
```verilog
    assign A_gt_B = (A > B);
    assign A_lt_B = (A < B);
    assign A_eq_B = (A == B);
```
### 4.4 ⚠️ 核心难点：竞争与冒险现象 (Hazards)
当纯数字逻辑走向实际物理电路时，不可避免的延迟问题。
*   **竞争 (Race)**：两个输入信号经过不同的门和导线，产生时延，到达输出端时间有先后。
*   **冒险 (Hazard)**：由于竞争，导致输出产生了非预期的极短错误脉冲（**毛刺 / Glitch**）。
*   **产生条件**：若逻辑表达式可化简为 $Y = A + A'$ 或 $Y = A \cdot A'$，当 A 状态跳变时必存冒险。
*   **消除方法**：
    *   *硬件级*：接入滤波电容、引入选通脉冲、修改逻辑加冗余项（如 $Y = AB + A'C$，加冗余项修改为 $Y = AB + A'C + BC$）。
    *   *FPGA设计级*：使用**格雷码**（每次只变一位，破坏产生条件）、**使用D触发器同步设计**（在时钟沿采样，屏蔽异步毛刺，这是现代系统中最核心的手段）。
### 4.5 综合设计实例与进阶自学
**实战案例：血型匹配控制系统**
*任务：判断输血是否符合医疗规则（O输一切，AB接一切等）。*
1. **编码**：O=00, A=01, B=10, AB=11。
2. **真值表**：穷举16种受血/输血组合。
3. **化简表达式**：得出 $F = G'H' + H'I + G'J + IJ$。
4. **Verilog 实现**：既可以用 `assign` 配合逻辑运算符直接写表达式，也可以用 `if-else` 或 `case` 列举所有 $F=1$ 的情况。
**🚀 进阶自学：超前进位加法器 (CLA - Carry Look-Ahead Adder)**
解决串行加法器太慢的问题，这是理解现代CPU算术逻辑单元(ALU)高性能的基石。
*   **核心思想**：直接利用初始输入信号（$A_0 \sim A_3$, $B_0 \sim B_3$, $C_0$），通过复杂的逻辑门，**一步到位同时算出所有的进位信号**，无需等待前一级的运算结果。
*   引入两个中间变量：**生成信号 (Generate, $G_i = A_i B_i$)** 和 **传播信号 (Propagate, $P_i = A_i \oplus B_i$)**。
*   **代价**：速度极快（典型的“空间换时间”应用），但随着位数的增加，门电路会变得极其庞大复杂。
