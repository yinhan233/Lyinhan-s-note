## 模块一：核心器件 —— 74161 同步二进制计数器

> [!abstract] 特点：它是一个自带加法功能和状态重置功能的“黑盒”。你只需要给它时钟信号（Clock），它就能自己往上数数。

### 1. 核心工作状态（看懂真值表即可）
74161有四个核心操作，优先级从高到低：
1. **清零 (置0)**：最高优先级。信号一来，不管三七二十一，输出全部变成 `0000`。（PPT中分为异步清零和同步清零）。
2. **预置数 (Load)**：你可以强行塞一个特定的数字（比如`1010`）给它，让它从这个数字开始数。
3. **保持 (Hold)**：暂停计数，记住当前数字。
4. **计数 (Count)**：每个时钟上升沿，数字 `+1`。

### 2. 什么是“模(M) / M进制”？
- **大白话**：计数器数了多少个数就回到原点，它就是**模几(Mod-M)**的计数器。
- **例子**：一个从 `0000` 数到 `1111` (0-15) 再回到 `0000` 的计数器，包含16个状态，叫 **模16 (16进制)** 计数器。

## 模块二：核心应用 —— 分频器设计 (Verilog)

> [!tip] 什么是分频器？
> 现有一个主板提供的很快的系统时钟（比如 50MHz），但我只需要一个很慢的时钟（比如 1Hz 拿来做秒表）。**分频器就是通过计数器，把高频时钟“降速”成低频时钟。**

### 1. 偶数分频公式
- **需求**：将 $f_{in}$ 分频为 $f_{out}$
- **分频系数 N**：$N = f_{in} / f_{out}$ (N必须为偶数)
- **代码逻辑**：计数器从 $0$ 数到 $N/2 - 1$ 时，输出信号翻转（0变1，1变0），同时计数器清零重新数。

### 2. 典型 Verilog 模板 (例：50MHz 变成 1Hz)
$N = 50,000,000 / 1 = 50,000,000$。翻转点为 $N/2 - 1 = 24,999,999$。

```verilog
module div_1hz(
    input clk_50mhz,  // 输入：50MHz高频时钟
    output reg clk_1hz // 输出：1Hz低频时钟
);
  
    // 定义一个足够大的计数器 (2500万需要至少25位二进制)
    reg [24:0] count; 
  
    always @(posedge clk_50mhz) begin
        if (count == 25000000 - 1) begin // 记到 N/2 - 1 的时候
            count <= 0;                  // 计数器归零
            clk_1hz <= ~clk_1hz;         // 输出时钟翻转！
        end 
        else begin
            count <= count + 1;          // 正常计数
        end
    end
endmodule
```

## 模块三：核心灵魂 —— 有限状态机 (FSM)

> [!important] 计算机专业必考/必懂
> 状态机 (Finite-State Machine) 是数字逻辑和底层软件设计的核心思维。**状态图 -> 逻辑转换 -> Verilog代码** 是一套标准流程。

### 1. 状态机的三种描述方式（Verilog）
老师在PPT里提到了三种写法，作为开发人员，**强烈建议在考试和工程中使用“三段式（三个always过程）”描述**，条理最清晰，最不容易扣分。
- **现态 (CS - Current State)**：描述状态的转移（受时钟控制，时序逻辑）。
- **次态 (NS - Next State)**：根据当前状态和输入，决定下一个状态是什么（组合逻辑）。
- **输出 (OL - Output Logic)**：根据当前状态（和输入），决定输出是什么（组合逻辑）。

### 2. 经典例题：“101”序列检测器
**需求**：串行输入一堆 0 和 1（如 `1 1 0 0 1 1 1 0 1 1`），当连续出现 `101` 时，输出 `1`，否则输出 `0`。

**状态机设计步骤**：
1. **S0 (初始态)**：啥都没收到。
2. **S1 (收到1)**：收到了 `1`，进度 1/3。
3. **S2 (收到10)**：收到了 `10`，进度 2/3。
4. **S3 (收到101)**：收到了 `101`，成功！输出1。

**Verilog 完美三段式实现（带详尽注释）**：
```verilog
module seq_detect_101(
    input clk, clr, x,  // clk:时钟, clr:异步复位, x:输入序列
    output reg z        // z:检测结果输出
);
  
    // 1. 定义状态 (强烈建议使用独热码或格雷码，这里用格雷码)
    parameter S0 = 2'b00, 
              S1 = 2'b01, 
              S2 = 2'b11, 
              S3 = 2'b10;
            
    reg [1:0] state, next_state;

    // --- 第一段：同步时序逻辑，更新当前状态 (CS) ---
    always @(posedge clk or posedge clr) begin
        if (clr) 
            state <= S0; // 异步复位回到初始状态
        else 
            state <= next_state; // 时钟到来，状态推进
    end

    // --- 第二段：组合逻辑，根据输入决定下一个状态 (NS) ---
    always @(*) begin // 或者 always @(state or x)
        case(state)
            S0: if(x==1) next_state = S1; else next_state = S0;
            S1: if(x==0) next_state = S2; else next_state = S1;
            S2: if(x==1) next_state = S3; else next_state = S0;
            S3: if(x==0) next_state = S2; else next_state = S1; // S3允许重叠检测
            default: next_state = S0;
        endcase
    end

    // --- 第三段：组合逻辑，决定输出 (OL) ---
    always @(*) begin // 或者 always @(state)
        if (state == S3) 
            z = 1'b1; // 只有在S3状态才输出1
        else 
            z = 1'b0;
    end

endmodule
```

## 模块四：⚠️ Verilog 开发与考试“避坑指南”
*(总结自PPT第31页，千万别在这里丢分)*

> [!warning] 综合报错雷区 (Must Know)
> 1. **物理隔离**：组合逻辑（电路）和时序逻辑（触发器）**尽量分开写**到不同的 `always` 块里（参考上面的三段式）。
> 2. **专一原则**：一个变量（如 `count` 或 `state`）**绝对不能**在两个或以上的 `always` 块里被赋值！否则综合器会报错（多驱动冲突）。
> 3. **赋值符号不可混用**：
>    - **时序逻辑**（带 `@(posedge clk)` 的）：全部使用 **非阻塞赋值 `<=`**。
>    - **组合逻辑**（带 `@(*)` 的）：全部使用 **阻塞赋值 `=`**。

## 🧠 快速自测小习题

**习题 1：基础计算**
你要设计一个单片机上的流水灯，系统时钟是 100 MHz。你想让流水灯每 0.5 秒（即 2 Hz）闪烁一次。请问你的计数器代码中，`if(count == ???)` 这里应该填什么数字？
> **答案**：分频系数 $N = 100,000,000 / 2 = 50,000,000$。翻转点为 $N/2 - 1 = 24,999,999$。所以填 `24999999`。

**习题 2：读码识图**
阅读上文的“101序列检测器”的**第二段代码（次态跳转）**。如果在状态 `S3` (已经检测到101) 时，此时输入 `x=0`，下一个状态为什么跳转到了 `S2` 而不是归零到 `S0`？
> **答案**：因为题目隐含要求“允许重叠检测”。之前收到了 `101`，最后一个 `1` 可以作为下一个 `10` 的开头。当输入 `x=0` 时，手里其实已经构成了 `10`，正好对应状态 `S2`（进度2/3）。这也是状态机思维中最容易出错的考察点。

**习题 3：纠错题**
下面这段 Verilog 代码有一个致命错误，请指出：
```verilog
always @(posedge clk) begin
    a = b & c;
    count = count + 1;
end
```
> **答案**：时序逻辑块（由时钟上升沿触发）内部应该强制使用非阻塞赋值 `<=`。代码中使用了阻塞赋值 `=`，是不符合规范的。应改为 `count <= count + 1;`。
