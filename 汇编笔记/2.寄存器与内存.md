## 一、 寄存器与内存基础
### 1. CPU 核心器件
CPU 主要由运算器、控制器和寄存器等器件构成，这些器件通过内部总线相连，协同完成 CPU 的工作：
- **运算器**：进行信息处理（运算单元）。
- **寄存器**：进行信息存储（存储单元）。
- **控制器**：负责控制各种器件工作（控制单元）。
> **注**：在 8086 CPU 中，所有寄存器都是 **16 位**的，可以存放两个字节的数据。
### 2. 8086 寄存器分类
8086 CPU 共有 **14 个 16 位寄存器**，按功能可分为以下 4 大类：
#### 2.1 通用寄存器（数据寄存器）
- 均为 16 位，可拆分为**两个独立的 8 位寄存器**使用（高 8 位 H + 低 8 位 L），即：`AX` → `AH/AL`、`BX` → `BH/BL`、`CX` → `CH/CL`、`DX` → `DH/DL`。
- 各自有专属的特殊用途：
    - **AX (Accumulator)**：累加器，算术运算、I/O 操作的默认寄存器。
    - **BX (Base)**：基址寄存器，常用于存放内存基地址。
    - **CX (Count)**：计数寄存器，循环指令（Loop）、字符串操作的默认计数器。
    - **DX (Data)**：数据寄存器，配合 `AX` 进行 32 位乘除运算，或存放 I/O 端口地址。
#### 2.2 变址与指针寄存器（地址寄存器）
- **SI (Source Index)** / **DI (Destination Index)**：源变址与目的变址寄存器，常用于字符串操作和变址寻址。
- **SP (Stack Pointer)**：堆栈指针寄存器，始终指向栈顶，配合 `SS` 段寄存器管理堆栈。
- **BP (Base Pointer)**：基址指针寄存器，指向堆栈内某一位置，默认配合 `SS` 用于访问堆栈中的数据。
#### 2.3 指令指针寄存器 IP
- 与**代码段寄存器 CS** 配合，计算下一条要执行指令的物理地址：`物理地址 = CS × 16 + IP`。
- 程序运行时 `IP` 会自动递增，从而控制指令的执行顺序。
- 注意：用户不能通过 MOV 指令直接修改 IP 和 CS 的值，必须通过转移指令（如 JMP、CALL 等）或 Debug 的 `R` 命令来修改。
#### 2.4 段寄存器
实现 8086 的**分段存储管理**，每个段寄存器对应一个内存段的基地址：
- **CS (Code Segment)**：代码段，存放程序指令。
- **SS (Stack Segment)**：堆栈段，存放堆栈数据。
- **DS (Data Segment)**：数据段，存放程序运行时的普通数据。
- **ES (Extra Segment)**：附加段，常用于字符串操作的目的数据段。
#### 2.5 标志寄存器 PSW (FLAGS)
16 位寄存器，其中 9 位有效（6 个状态标志 + 3 个控制标志），用于反映 CPU 运算结果的状态和控制 CPU 的操作：
- **状态标志**：`CF`（进位）、`PF`（奇偶）、`AF`（辅助进位）、`ZF`（零）、`SF`（符号）、`OF`（溢出）。
- **控制标志**：`TF`（陷阱）、`IF`（中断允许）、`DF`（方向）。
### 3. 小端模式与字长
8086 CPU 采用小端存储（Little-Endian）模式，规则如下：
> 低位字节存放在低地址内存单元，高位字节存放在高地址内存单元。
- **字长（Word Size）**：指 CPU 一次能并行处理的二进制数据的位数。8086 CPU 的字长为 **16 bit**。
- **内存存储示例**：若要在 `2000:0000` 处存放一个 16 位的字 `1234H`：
    - `2000:0000` 存放低字节 `34H`。
    - `2000:0001` 存放高字节 `12H`。

## 二、 内存地址的表示与访问
### 1. 物理地址计算
8086 CPU 有 **20 根地址总线**，其寻址范围为 $2^{20}$ Byte（即 1MB）。
然而，8086 是 16 位 CPU，其内部寄存器最多只能处理 16 位数据（即 64KB 寻址能力）。为了解决这个问题，8086 采用了“段地址 + 偏移地址”的合成机制：
> **物理地址 = 段地址 × 16 + 偏移地址**

_注：段地址乘 16，在二进制下相当于将其向左平移 4 位，从而凑出 20 位基础地址，再加上 16 位的偏移地址，最终得出 20 位的物理地址。_
### 2. 数据段寄存器 DS
`DS` 专门用于存放**数据段的段地址**。所有通过 `[偏移地址]` 访问内存的操作，默认使用 `DS` 作为段寄存器。
核心限制：8086 硬件不支持将立即数直接送入段寄存器。
```
; ❌ 错误写法：不能直接把立即数赋值给 DS
MOV DS, 1000H  

; ✅ 正确写法：立即数 → 通用寄存器 → 段寄存器
MOV BX, 1000H  ; 先把段地址存入通用寄存器
MOV DS, BX     ; 再传送到 DS
```
### 3. 内存的读写（字节与字）
使用不同宽度的寄存器，决定了读写内存的长度。
**字节读写（8 位）**，以 `DS=1000H` 为例：

|**操作类型**|**示例代码**|**功能说明**|
|---|---|---|
|读内存|`mov al, [0]`|读取物理地址 `10000H` 的 1 字节数据，存入 `AL`|
|写内存|`mov [0], al`|将 `AL` 中的 1 字节数据，写入物理地址 `10000H`|

**字读写（16 位）**，遵循小端存储，一次操作连续 2 个单元：

|**操作类型**|**示例代码**|**功能说明**|
|---|---|---|
|读字|`mov ax, [0]`|读 `10000H`（低字节）和 `10001H`（高字节），拼成字存入 `AX`|
|写字|`mov [0], cx`|将 `CX` 的低 8 位写入 `10000H`，高 8 位写入 `10001H`|

## 三、 数据传送与算术运算
### 1. MOV 指令
将**源操作数**的内容**复制**到**目的操作数**中，源操作数保持不变。
- **格式**：`MOV 目的操作数, 源操作数`
- **特性**：不影响任何标志位（CF、OF、SF、ZF 等均不变）。
#### 合法与禁止用法

|**合法指令格式**|**示例**|**补充说明**|
|---|---|---|
|`mov 寄存器, 立即数`|`mov ax, 8`|/|
|`mov 寄存器, 寄存器`|`mov ax, bx`|/|
|`mov 寄存器, 内存`|`mov ax, [0]`|/|
|`mov 内存, 寄存器`|`mov [0], ax`|/|
|`mov 段寄存器, 寄存器`|`mov ds, ax`|CS 除外，绝不能用 MOV 修改 CS|
|`mov 寄存器, 段寄存器`|`mov ax, ds`|合法|

❌ 常见错误用法：
1. **两个内存单元直接传送**：必须用寄存器中转（`MOV AX, [1000H]` -> `MOV [2000H], AX`）。
2. **段寄存器之间直接传送**：必须用通用寄存器中转（`MOV AX, ES` -> `MOV DS, AX`）。
3. **操作数尺寸不匹配**：`MOV AL, 1234H`（大小不匹配）。
4. **内存尺寸模糊**：当一方是内存，另一方是立即数时，需显式声明，如 `MOV WORD PTR [0], 1234H` 或 `MOV BYTE PTR [0], 12H`。
### 2. ADD 与 SUB 指令
将结果存回**目的操作数**中。
- **格式**：`ADD/SUB 目的操作数, 源操作数`
- **特性**：会影响算术标志位（CF、OF、SF、ZF、AF、PF）。
- **限制**：操作数组合与 `MOV` 基本一致，但不支持段寄存器参与运算。
#### 核心标志位影响分析

|**标志位**|**含义**|**ADD 置 1 条件**|**SUB 置 1 条件**|
|---|---|---|---|
|**CF（进/借位）**|无符号数边界|结果超出表示范围（进位）|被减数 < 减数（需借位）|
|**OF（溢出）**|有符号数边界|结果超出有符号数范围|结果超出有符号数范围|
|**ZF（零标志）**|运算结果为 0|结果等于 0|结果等于 0|
|**SF（符号位）**|结果的最高位|结果为负数（最高位为 1）|结果为负数（最高位为 1）|

#### 进阶：带进/借位运算（ADC / SBB）
常配合 `ADD` 和 `SUB` 用于**多字（大于 16 位）数据**的运算。
- **ADC (Add with Carry)**：`目的操作数 = 目的 + 源 + CF`
- **SBB (Subtract with Borrow)**：`目的操作数 = 目的 - 源 - CF`
```
; 示例：计算 32 位无符号数加法 (0x12345678 + 0x9ABCDEF0)
; 小端视角：低字在先，高字在后。AX处理低字，BX处理高字
MOV AX, 5678H
ADD AX, DEF0H   ; 低字相加，产生进位 CF=1
MOV BX, 1234H
ADC BX, 9ABCH   ; 高字相加，加上低字产生的进位 CF
```

## 四、 转移指令 (JMP)
### 1. 段间转移（远转移 Far JMP）
**功能**：同时修改 `CS` 和 `IP`，跳到另一个代码段执行。
- **格式**：`jmp far ptr 标号` 或 `jmp 段地址:偏移地址`
- **特性**：唯一能用普通指令同时修改 CS 和 IP 的方法。
### 2. 段内转移（近转移 Near JMP）
**功能**：只修改 `IP`，不修改 `CS`，在同一个代码段内跳转。
- **段内寄存器间接转移**：`jmp 16位通用寄存器`（如 `jmp ax`，直接将 AX 的值赋给 IP）。
- **段内直接短转移（常用）**：`jmp short 标号`。跳转范围 `-128 ~ +127` 字节。
- **段内直接近转移**：`jmp near ptr 标号`。跳转范围 `-32768 ~ +32767` 字节。

## 五、 堆栈 (STACK)
### 1. 机制与寄存器
8086 CPU 内置硬件栈机制，操作规则为**后进先出 (LIFO)**。
- **基本单位**：所有栈操作均以字（16 位 / 2 字节）为基本单位。
- **SS (栈段寄存器)**：存储栈段的基地址。
- **SP (栈顶指针)**：存储栈顶的偏移地址。`SS:SP` 永远指向当前栈顶元素。
### 2. PUSH 与 POP 执行流程
- **PUSH 入栈**：先移指针，后写数据。
    1. 栈向低地址生长：`SP = SP - 2`。
    2. 将 16 位寄存器数据写入 `SS:SP` 指向的字单元。
- **POP 出栈**：先读数据，后移指针。
    1. 读取 `SS:SP` 指向的 16 位数据到寄存器。
    2. 栈向高地址退回：`SP = SP + 2`。
### 3. 栈顶超界警告
8086 硬件**不提供栈超界保护机制**。程序员必须手动规划并分配足够的栈空间，否则过度 `PUSH` 会导致数据覆盖（入栈溢出），过度 `POP` 会读取到无用垃圾数据（出栈溢出）。

## 六、 DEBUG 核心调试命令
在命令行使用 Debug 调试汇编代码时的核心指令集：

| **命令**  | **全称**     | **用法与说明**                                                                                                                                                                  |
| ------- | ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`R`** | Register   | **查看/修改寄存器**。<br>用法1：直接敲 `R` 查看所有寄存器状态。<br>用法2：`R AX` 修改 AX 的值。                                                                                                            |
| **`D`** | Dump       | **查看内存内容**。<br>用法：`D 段地址:偏移地址` 或 `D 起始 结束`。<br>左侧为地址，中间为十六进制数据，右侧为 ASCII 码。                                                                                                |
| **`E`** | Enter      | **修改内存内容**。<br>用法1：`E 地址`，按空格逐字节修改。<br>用法2：`E 0100 41 42 "Hello"` 批量写入数据或字符串。                                                                                              |
| **`U`** | Unassemble | **反汇编**。<br>用法：`U 地址`。<br>将内存中的机器码翻译为汇编指令。注意：内存中数据和代码没有物理区别，务必确保 `U` 的地址确实是代码段。                                                                                            |
| **`A`** | Assemble   | **汇编**。<br>用法：`A 地址`。<br>直接敲入汇编助记符指令，Debug 会自动翻译为机器码并写入内存。回车两次退出。                                                                                                          |
| **`T`** | Trace      | **单步执行**。<br>执行 `CS:IP` 指向的一条指令。<br>极易错点：遇到 `INT` 中断（如 `INT 21H`）时，**切勿使用 T 命令**，否则会单步跟入系统底层导致死机。                                                                          |
| **`G`** | Go / `-P`  | **全速执行 / 跳过执行**。<br>用法1：`G` 全速执行到底。<br>用法2：`G=起始 断点`（如 `G=0100 0110`），执行并在断点处停下。这是越过 `INT` 中断的常用方法。<br>用法3：遇到 `INT` 时，直接输入 `P`（Proceed）命令，可一键将其执行完毕（类似现代 IDE 的 Step Over）。 |
