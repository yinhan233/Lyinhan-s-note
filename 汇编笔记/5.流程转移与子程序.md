## 一、 段式内存模型与 offset 操作符
### 1. 8086 内存地址基础
8086 CPU 采用**段式存储模型**，物理地址计算公式为：`物理地址 = 段地址 × 16 + 偏移地址`。

* **代码段**：专门存放程序指令。段地址存放在 **<font color="#D93A49">CS</font>**（代码段寄存器），当前待执行指令的偏移地址存放在 **<font color="#D93A49">IP</font>**（指令指针寄存器）。CPU 始终执行 `CS:IP` 指向的内存单元中的指令。
* **标号**：汇编语言中用来标记内存地址的符号，本质是该地址相对于所在段起始地址的偏移量。
### 2. offset 操作符
**作用**：在编译阶段由汇编器（Compiler）计算并返回标号在其所在段内的**偏移地址**。
* **格式**：<font color="#1D953F">**offset**</font> `标号`
* **代码示例**：
```assembly
assume cs:codeseg
codeseg segment
start:  mov ax, offset start  ; 等价于 mov ax, 0（start 是段内第一条指令，偏移为 0）
s:      mov ax, offset s      ; 等价于 mov ax, 3（上一条指令占 3 字节，s 的偏移为 3）
codeseg ends
end start
```

## 二、 灵活的寻址方式与内存操作
### 1. 在哪里？有多长？(寻址的两个基本问题)
在汇编中，对数据进行操作时必须明确两个问题：
1. **地址在哪里？** （通过寄存器或内存寻址方式给出）
2. **数据有多长？** （是 Byte 还是 Word？）
    * **通过寄存器指明**：如 `mov ax, [0]` (16 位字)，`mov al, [0]` (8 位字节)。
    * **通过 X ptr 指明**：如果没有寄存器参与，必须显式声明。例如：<font color="#1D953F">**word ptr**</font> `[bx]`（操作 1 个字，2 字节），<font color="#1D953F">**byte ptr**</font> `[bx]`（操作 1 个字节）。
### 2. 用于内存寻址的寄存器
在 8086 中，**只有 4 个寄存器**可以放在中括号 `[...]` 中进行内存寻址：
* **基址寄存器**：**<font color="#D93A49">BX</font>**（默认段为 DS）、**<font color="#D93A49">BP</font>**（默认段为 SS）
* **变址寄存器**：**<font color="#D93A49">SI</font>**（源变址，默认段为 DS）、**<font color="#D93A49">DI</font>**（目的变址，默认段为 DS）
* *注意：这四个寄存器可以单独使用，也可以按照特定规则组合（如 `[bx+si]`），但 `bx` 和 `bp` 不能同时出现，`si` 和 `di` 也不能同时出现。*
### 3. 多种寻址方式演示与综合应用
汇编提供了极其灵活的寻址方式，以对应高级语言中的一维数组、二维数组及结构体。
```assembly
assume cs:code, ds:data
data segment
    db 'unix'       ; 偏移地址 0-3
    db 'linux'      ; 偏移地址 4-8
data ends

code segment
start:
    mov ax, data
    mov ds, ax
  
    ; 1. [bx+idata] 方式：常用于处理一维数组，idata 可看作数组首地址，bx 看作索引
    mov bx, 0
    mov al, [bx+4]     ; 读取 'linux' 的首字母 'l'，等价于 4[bx]
  
    ; 2. [bx+si] 方式：常用于二维数组，bx 代表行首地址，si 代表列偏移
    mov bx, 0
    mov si, 2
    mov al, [bx+si]    ; 读取 'unix' 的第 3 个字母 'i'
  
    ; 3. [bx+si+idata] 方式：常用于结构体数组。idata 是结构体数组首地址，bx 是结构体偏移，si 是结构体内成员偏移
    mov bx, 0
    mov si, 1
    mov al, [bx+si+4]  ; 读取 'linux' 的第 2 个字母 'i'
  
    mov ax, 4c00h
    int 21h
code ends
end start
```
### 4. 大小写字母转换 (处理字符问题)

大小写转换的本质是修改 ASCII 码的特定二进制位：
* 小写字母的第 5 位（从 0 开始算）恒为 `1`，大写字母恒为 `0`。
* **转大写**：用 <font color="#1D953F">**and**</font> 指令清零第 5 位。如 `and al, 11011111b` (或 `DFH`)
* **转小写**：用 <font color="#1D953F">**or**</font> 指令置位第 5 位。如 `or al, 00100000b` (或 `20H`)
### 5. 用 div 指令实现除法
**<font color="#1D953F">div</font>** 是无符号除法指令，使用时必须注意除数和被除数的长度匹配关系：

| 除数长度 | 被除数位置 (默认) | 商的位置 | 余数的位置 | 示例指令 |
| :--- | :--- | :--- | :--- | :--- |
| **8 位** (Byte) | **<font color="#D93A49">AX</font>** (16 位) | **<font color="#D93A49">AL</font>** | **<font color="#D93A49">AH</font>** | `div bl` 或 `div byte ptr [bx]` |
| **16 位** (Word) | **<font color="#D93A49">DX</font>** (高 16) + **<font color="#D93A49">AX</font>** (低 16) | **<font color="#D93A49">AX</font>** | **<font color="#D93A49">DX</font>** | `div cx` 或 `div word ptr [bx]` |

**代码示例：计算 100001 ÷ 100**
```assembly
; 100001 大于 65535，必须用 32 位被除数，除数用 16 位
mov dx, 1          ; 100001 的十六进制为 186A1H。高 16 位 0001H 放入 dx
mov ax, 86A1H      ; 低 16 位 86A1H 放入 ax
mov bx, 100        ; 除数 100 放入 bx
div bx             ; 执行除法后：ax 存商 (03E8H, 即 1000)，dx 存余数 (0001H)
```
### 6. 用 dup 设置内存空间
**<font color="#1D953F">dup</font>** 与 `db`、`dw`、`dd` 配合使用，用于批量分配内存空间，非常适合初始化连续的零空间。
* 格式：`db 重复次数 dup (重复的字节型数据)`
* 示例：
    * `db 10 dup (0)`：定义 10 个字节，全为 0。
    * `db 3 dup ('abc')`：定义 9 个字节，内容为 `'abcabcabc'`。

## 三、 流程转移与转移指令

默认情况下 CPU 按内存地址递增的顺序逐条执行指令。**转移指令**通过修改 **<font color="#D93A49">IP</font>**（或同时修改 **<font color="#D93A49">CS</font>** 和 **<font color="#D93A49">IP</font>**），强制 CPU 跳转到指定地址执行代码。
### 1. 转移指令分类
* **段内转移**：仅修改 **<font color="#D93A49">IP</font>**，跳转范围限制在当前段内。又细分为：
    * **段内短转移 (short)**：IP 修改范围 `-128 ~ +127`（8 位相对位移）。
    * **段内近转移 (near)**：IP 修改范围 `-32768 ~ +32767`（16 位相对位移）。
* **段间转移 (far)**：同时修改 **<font color="#D93A49">CS</font>** 和 **<font color="#D93A49">IP</font>**，可跳转到内存任意代码段。
### 2. jmp 无条件转移指令格式汇总

| 指令格式 | 分类 | 寻址原理 | 示例 |
| :--- | :--- | :--- | :--- |
| `jmp short 标号` | 段内短转移 | IP = IP + 8 位相对位移 | `jmp short s` |
| `jmp near ptr 标号` | 段内近转移 | IP = IP + 16 位相对位移 | `jmp near ptr s` |
| `jmp far ptr 标号` | 段间远转移 | CS = 标号段地址，IP = 标号偏移 | `jmp far ptr s` |
| `jmp 16位寄存器` | 段内转移 | IP = 寄存器的值 | `jmp bx` |
| `jmp word ptr 内存` | 段内转移 | 从内存读取 1 个字赋给 IP | `jmp word ptr [bx]` |
| `jmp dword ptr 内存` | 段间转移 | 内存低字给 IP，高字给 CS | `jmp dword ptr [bx]` |
### 3. jcxz 与 loop 指令 (相对转移机制)

这两者均属于**基于 8 位相对位移的短转移**，机器码中只存储位移量（范围 `-128 ~ 127`），这使得代码段具有可浮动装配的特性。
* **<font color="#1D953F">jcxz</font>** `标号` (有条件跳转)：
    * **不修改 CX 的值**。
    * 判断：若 `(CX) == 0`，则发生跳转；若不为 0 则继续向下执行。
* **<font color="#1D953F">loop</font>** `标号` (循环控制)：
    * **先自动执行 `CX = CX - 1`**。
    * 判断：若 `(CX) != 0`，则发生跳转；若为 0 则结束循环向下执行。

## 四、 模块化程序设计 (子程序)
汇编语言的子程序机制依赖于函数的调用（`call`）与返回（`ret`），同时需要解决参数传递和寄存器冲突问题。
### 1. call 与 ret 指令详解
**<font color="#1D953F">call</font>** 指令执行时**先将返回地址压入栈中**，再跳转到子程序。**<font color="#1D953F">ret</font>** 从栈中弹出地址恢复流程。

| 调用指令 | 等价操作 (入栈+跳转) | 对应的返回指令 | 等价操作 (出栈) |
| :--- | :--- | :--- | :--- |
| `call 标号` (段内) | `push IP` <br> `jmp near ptr 标号` | **<font color="#1D953F">ret</font>** | `pop IP` |
| `call far ptr 标号` (段间) | `push CS` <br> `push IP` <br> `jmp far ptr 标号` | **<font color="#1D953F">retf</font>** | `pop IP` <br> `pop CS` |
### 2. 子程序的参数传递方案
1. **寄存器传递**：最快。将参数和结果存放于 **<font color="#D93A49">AX</font>**、**<font color="#D93A49">BX</font>** 等通用寄存器中。缺点是寄存器数量有限。
2. **内存传递**：传递批量数据（如字符串）。将内存首地址存入 **<font color="#D93A49">SI</font>** 等指针寄存器传递。
3. **栈传递 (最通用)**：调用者将参数压入栈，子程序通过基址寄存器 **<font color="#D93A49">BP</font>** 访问栈帧提取参数。这是 C 语言等高级语言底层的实现逻辑。
### 3. 子程序的寄存器保护 (标准框架)
如果在子程序中修改了主程序正在使用的寄存器，会导致不可预知的 Bug（寄存器冲突）。
**核心规范**：在子程序开头将用到的寄存器入栈，结尾按**相反顺序**出栈。
```assembly
capital:                ; 子程序标签
    push cx             ; 1. 保护主程序的寄存器状态
    push si
  
change: 
    mov cl, [si]
    mov ch, 0
    jcxz ok             ; 遇到 '\0' 结束
    and byte ptr [si], 11011111b ; 转大写
    inc si
    jmp short change
  
ok: 
    pop si              ; 2. 恢复寄存器（注意出栈顺序必须与入栈严格相反！）
    pop cx
    ret                 ; 3. 返回主程序
```

## 五、 标志寄存器 (Flag Register)

8086 的 flag 寄存器按位独立工作，用于记录指令执行结果的状态。最核心的 5 个标志位如下：

| 标志位 | 名称 | 位置 | 核心含义 | 取值规则判定 |
| :---: | :--- | :---: | :--- | :--- |
| **<font color="#D93A49">ZF</font>** | 零标志 | 第 6 位 | 结果是否为 0 | `ZF=1`：结果为 0 <br> `ZF=0`：结果非 0 |
| **<font color="#D93A49">PF</font>** | 奇偶标志 | 第 2 位 | 结果二进制位中 1 的个数 | `PF=1`：1 的个数为偶数 <br> `PF=0`：奇数 |
| **<font color="#D93A49">SF</font>** | 符号标志 | 第 7 位 | 有符号数结果的正负 | `SF=1`：结果为负数 <br> `SF=0`：非负数 |
| **<font color="#D93A49">CF</font>** | 进位标志 | 第 0 位 | **无符号数**的进位/借位 | `CF=1`：有进位/借位 <br> `CF=0`：无 |
| **<font color="#D93A49">OF</font>** | 溢出标志 | 第 11 位 | **有符号数**是否发生溢出 | `OF=1`：发生溢出 <br> `OF=0`：未溢出 |

* **CF 与 OF 的根本区别**：**<font color="#D93A49">CF</font>** 针对无符号数运算；**<font color="#D93A49">OF</font>** 针对有符号数运算。两者相互独立，互不干涉。
* **指令影响**：`add`、`sub`、`mul`、`div` 等运算指令通常会影响标志位；`mov`、`push`、`pop` 等传送指令通常**不影响**标志位。

## 六、 cmp 指令与高级条件转移
### 1. cmp 比较指令
* **格式**：<font color="#1D953F">**cmp**</font> `操作对象1, 操作对象2`
* **本质**：执行 `操作对象1 - 操作对象2` 的减法运算。
* **特性**：**不保存运算结果，只修改标志寄存器**。后续条件转移指令根据这些标志位决定是否跳转。
### 2. 条件转移指令 (if-else 的底层实现)
汇编通过 `cmp` + `jxxx` 系列指令直接实现了高级语言的 `if` 逻辑。
* **判等跳转**：`je` (相等 ZF=1) / `jne` (不等 ZF=0)
* **无符号数判定**：
    * `jb` (低于 CF=1) / `jnb` (不低于 CF=0)
    * `ja` (高于 CF=0 且 ZF=0) / `jna` (不高于 CF=1 或 ZF=1)
**实战示例**：用汇编实现 C 语言逻辑 `if(ah == bh) { ah += ah; } else { ah += bh; }`
```assembly
    cmp ah, bh
    je is_equal   ; 如果相等 (ZF=1)，跳转到 is_equal 标签
  
    ; 这里是 else 分支 (不等时执行)
    add ah, bh  
    jmp short ok  ; else 执行完毕，必须无条件跳过 if 分支！
  
is_equal:         ; 这里是 if 分支 (相等时执行)
    add ah, ah  
  
ok:               ; 流程汇合点
    ret
```

## 七、 串传送指令与 rep 前缀

用于极高效率地实现内存数据块的批量复制，高度依赖 **<font color="#D93A49">DF</font>** (方向标志位)、**<font color="#D93A49">CX</font>** (计数器) 以及 **<font color="#D93A49">SI</font>** 和 **<font color="#D93A49">DI</font>**。
### 1. DF 方向标志位
* `DF = 0`：正向传送，操作后 `si`、`di` **递增**。通过 <font color="#1D953F">**cld**</font> 指令设置。
* `DF = 1`：反向传送，操作后 `si`、`di` **递减**。通过 <font color="#1D953F">**std**</font> 指令设置。
### 2. rep 与串传送组合运用
* <font color="#1D953F">**movsb**</font> (字节传送)：将 `ds:[si]` 的一字节复制到 `es:[di]`。
* <font color="#1D953F">**movsw**</font> (字传送)：将 `ds:[si]` 的一个字（两字节）复制到 `es:[di]`。
* <font color="#1D953F">**rep**</font>：根据 **<font color="#D93A49">CX</font>** 的值，将后面的串传送指令**自动循环执行 CX 次**。
**终极代码优化对比 (复制 16 个字节)**：
```assembly
; 方案 A：手写普通 loop 循环 (耗时长，代码多)
    mov si, 0
    mov di, 16
    mov cx, 8
s:  mov ax, [si]
    mov es:[di], ax
    add si, 2
    add di, 2
    loop s

; 方案 B：使用 rep + movsw 硬件级传输 (极致精简)
    mov si, 0
    mov di, 16
    cld           ; 确认 DF=0，地址递增
    mov cx, 8     ; 传送 8 个字 (16 字节)
    rep movsw     ; 一行代码搞定！自动自增，自动循环 8 次
```
## DF 方向标志位 —— 搬运方向由它定
- `DF = 0`（`cld` 设置）→ **正向传送**  
    机器人搬完一次后，**地址增大**，也就是从前往后搬。  
    适合常规的“从低地址往高地址复制”。
- `DF = 1`（`std` 设置）→ **反向传送**  
    机器人搬完一次后，**地址减小**，也就是从后往前搬。  
    什么时候用？当源和目的内存有重叠，且目的地址高于源地址时，为了防止覆盖还没读的数据，就要从高往低搬。这和 `memmove` 的逻辑一样。
> `cld` = **CL**ear **D**irection flag → DF=0  
> `std` = **S**e**T** **D**irection flag → DF=1
