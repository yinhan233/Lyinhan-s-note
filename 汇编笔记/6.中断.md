### 第一部分：中断相关知识点（基础概念）
**1. 什么是中断？**
简单来说，中断就是CPU在执行程序时，突然发生了一件“紧急事件”，CPU不得不**暂停**手头的工作，去处理这个“紧急事件”（执行中断处理程序），处理完之后，再**回来**继续刚才的工作。  
**2. 中断的分类（按来源）**
*   **外部中断（硬件中断）：** 比如键盘按下一个键、鼠标移动，由外部设备引发。
*   **内中断（软件中断）：** 由CPU内部事件或程序指令引发。**不受中断允许标志位（IF）的控制**。
    *   由 `int n` 指令主动引发（n是中断号）。
    *   CPU执行出错（如除法溢出，中断号0）。
    *   为调试设置（如单步中断，中断号1；断点，中断号3）。  
      
**3. 中断向量表（核心重点！）**
CPU怎么知道遇到哪种中断该去执行哪段代码？答案就是**中断向量表**。
*   它就像一本“电话簿”，存放在内存的 `0000:0000` 到 `0000:03FF`（共1024个字节）区域。
*   系统支持 **256** 个中断（0 ~ 255或FFH）。
*   每个中断对应的处理程序入口地址占 **4个字节**（低2字节是IP偏移地址，高2字节是CS段地址）。
*   **寻址公式：** 如果中断号为 `n`，那么它的IP存放在 `n*4` 的地址，CS存放在 `n*4+2` 的地址。  
  
**4. 中断的处理过程（CPU自动完成）**
1. 取得中断类型码 `n`。
2. 标志寄存器（FR）入栈保存。
3. 清除 TF 和 IF 标志位（TF=0, IF=0）。
4. 当前代码段 `CS` 入栈，当前指令指针 `IP` 入栈。
5. 从中断向量表读取新的 CS 和 IP，**跳转去执行中断程序**。
*(处理完毕后，遇到 `iret` 指令，执行出栈操作，恢复IP、CS和FR，回到原程序。)*

### 第二部分：如何调用中断？
在汇编中，调用中断非常简单，主要有两种方式：  
**1. 隐式调用（触发异常）**  
不需要你写代码去调用，CPU遇到错误会自动触发。
*   例如：执行 `div` 指令除以0时，CPU会自动触发 **0号中断**。
*   例如：在Debug中按 `T` 键，CPU执行完一条指令后检测到TF=1，会自动触发 **1号中断**。  
  
**2. 显式调用（使用 `int` 指令）**  
格式：`int n` （n是你要调用的中断号，0~255）。  
这就像高级语言里的“函数调用”。最常用的是 **DOS功能调用 `int 21h`**。  
**举例：如何在屏幕显示一串字符？（调用 int 21h 的 9号功能）**  
```assembly
mov ah, 9           ; AH寄存器存入功能号9（表示显示字符串）
mov dx, offset str  ; DX寄存器存入字符串的偏移地址 (字符串必须以 '$' 结尾)
int 21h             ; 呼叫21号中断，DOS会根据AH=9去帮你把字符串打印出来
```

### 第三部分：如何自定义中断并且安装？（实战核心）
这是PPT中最难也是最精彩的部分。假设我们要自己写一个处理程序（比如0号除法溢出，或者自定义的7CH号中断），我们需要做三件事：**编写它 -> 把它搬到安全的内存 -> 登记到向量表**。
#### 步骤1：编写中断处理程序
中断处理程序必须常驻内存。为了防止运行完就被系统回收，一个巧妙的方法：  
**把字符串数据直接写在代码段里，并用 `jmp` 跳过它**。
```assembly
do0:
    jmp short do0start
    db "overflow!", 0  ; 字符串数据跟着代码走
do0start:
    ; 1. 保护用到的寄存器 (push)
    ; 2. 处理中断逻辑 (比如把 "overflow!" 打印到显存 0B800h 区域)
    ; 3. 恢复寄存器 (pop)
    iret               ; 【注意】中断返回必须用 iret，不能用 ret！
do0end: nop            ; 作为一个标记，用来计算这段代码的长度
```
#### 步骤2：安装中断程序（搬运代码）
我们写好了 `do0`，现在要把它复制到内存里一个“绝对安全、不会被别人覆盖”的地方。在DOS时代，`0000:0200` 到 `0000:02FF` 通常是安全的空闲区。  
使用 **串传送指令 `rep movsb`** 来搬运：
```assembly
; 设置源地址 (我们写的 do0 的位置)
mov ax, cs
mov ds, ax
mov si, offset do0 

; 设置目的地址 (0000:0200)
mov ax, 0
mov es, ax
mov di, 200h

; 设置搬运长度 (巧妙利用编译器计算: 结束标记 - 开始标记)
mov cx, offset do0end - offset do0 

; 设置搬运方向并搬运
cld             ; 正向搬运
rep movsb       ; 开始复制！
```
#### 步骤3：设置中断向量表（登记户口）
代码已经安静地躺在 `0000:0200` 了，现在要告诉CPU：“以后遇到这个中断，就去 `0000:0200` 找它”。
假设我们要替换 **0号中断**：
```assembly
mov ax, 0
mov es, ax

; 0号中断的 IP 存放在 0*4 = 0 的位置
mov word ptr es:[0], 200h    ; 将偏移地址 0200H 存入向量表
; 0号中断的 CS 存放在 0*4+2 = 2 的位置
mov word ptr es:[2], 0       ; 将段地址 0000H 存入向量表
```
*(如果是自定义7CH中断，地址就是 `7ch * 4` 和 `7ch * 4 + 2`)*

### 总结一下自定义中断的完整逻辑：

1. 你的主程序启动。
2. 主程序把 **自定义的中断代码** 复制到 `0:200`。
3. 主程序修改 **中断向量表**，把目标中断号（如0或7CH）的地址指向 `0:200`。
4. 主程序退出（或者继续执行引发中断的代码）。
5. 此时，哪怕主程序退出了，因为向量表已经改了，代码也写在了安全的 `0:200` 处。以后一旦发生该中断，CPU就会乖乖去执行你写的逻辑！ 
    
**特别注意的坑：**  
CPU在执行完 `mov ss, ax` 这类修改栈段寄存器的指令后，**绝对不会响应中断**！因为如果刚改了段地址 `ss`，还没来得及改偏移地址 `sp`，这时候发生中断去压栈，栈就崩溃了。所以修改栈必须连续写：  
```assembly
mov ss, ax
mov sp, 0  ; 这两句之间CPU绝对不会被打断
```
