# 第1章 软件工程概述 — 重点笔记

## 一、软件的定义与分类

- **软件 = 程序 + 文档 + 数据**
- **分类**：
  - **系统软件**：操作系统、编译程序、数据库管理系统等
  - **支撑软件**：软件开发工具、环境、管理工具等
  - **应用软件**：面向特定应用领域的软件

## 二、软件的基本特性（No Silver Bullet, Fred Brooks）

| 特性 | 含义 |
|------|------|
| **复杂性** | 软件实体比任何人类构造物都复杂 |
| **不可见性** | 软件结构无法用几何图形直观表示 |
| **服从性** | 软件须服从人为的惯例和规则 |
| **易变性** | 软件面临持续变更的压力 |

## 三、软件危机

- **表现**：规模大、复杂度增加、供需差增大、价格昂贵、开发速度慢、质量难以保证
- **两个核心问题**：
  1. **如何开发**满足用户需求的软件
  2. **如何维护**数量不断增长的现有软件
- **历史背景**：1968年NATO会议首次提出 **"软件危机"** 和 **"软件工程"** 术语

### 软件危机解决途径

- 重视**需求分析**
- 重视**设计和实现**
- 充分**测试**
- 加强**维护和管理**
- 采用统一的**方法论**

## 四、软件工程定义

- **Fritz Bauer 定义**：建立和使用一套合理的工程原则，以便经济地获得可靠的、在实际机器上高效运行的软件
- **B.W. Boehm 定义**：运用现代科学技术知识来设计并构造计算机程序及为开发、运行和维护这些程序所必需的相关文档资料

## 五、软件工程三要素

> **过程 + 方法 + 工具**

- **过程**：为获得高质量软件而需完成的一系列任务框架
- **方法**：完成任务的技术手段（如结构化方法、面向对象方法）
- **工具**：为方法提供自动或半自动的软件支撑环境

## 六、软件开发的本质

- **问题域** → （映射/抽象/建模） → **运行平台**
- 通过**抽象（建模）**分层控制复杂性

## 七、软件工程基本原理

- **推迟实现**：先分析设计，后编码
- **逐步求精**：由粗到细逐步展开
- **分解与抽象**：将复杂问题分解为可管理的子问题
- **信息隐蔽**：模块内部实现细节对外不可见
- **质量保证**：贯穿软件开发全过程

## 八、软件工程基本原则（B.W. Boehm 七条原则）

1. 分阶段的**生存周期**计划
2. 坚持进行**阶段评审**
3. 实行**严格的产品控制**（基线/变更控制）
4. 采用**现代程序设计技术**
5. 结果应能**清楚地审查**（明确职责）
6. 开发小组人员应**少而精**
7. 承认**不断改进**软件工程实践的必要性

## 九、软件工程方法学

| | 结构化方法 | 面向对象方法 |
|---|---|---|
| **起源** | 1968年 | 90年代成熟 |
| **核心思想** | 自顶向下、逐级细化 | 封装、继承、多态、复用 |
| **特点** | 功能分解 | 以对象为中心 |

## 十、重型 vs 轻型方法

- **重型方法**（如瀑布模型）：文档齐全、过程严格、计划驱动
- **轻型方法**（如敏捷开发）：重视代码和测试、快速迭代、响应变化
