# 第2章 软件过程及其模型 — 重点笔记

## 一、软件生存周期（SDLC）

### 三个时期

| 时期 | 阶段 |
|------|------|
| **定义时期** | 可行性分析、项目计划、需求分析 |
| **开发时期** | 软件设计、编码与测试 |
| **运行时期** | 运行与维护 |

## 二、软件过程

- **定义**：软件生存周期中一系列相关过程所涉及的活动
- **层次结构**：过程 → 活动 → 任务
- **软件过程模型（软件生存周期模型）**：软件过程的抽象表示

## 三、瀑布模型（1970, Winston Royce）

### 六个阶段（顺序展开）

> 计划 → 需求分析 → 设计 → 实现（编码） → 测试 → 维护

### 特点

- **顺序性**：前一阶段完成后才进入下一阶段
- **推迟实现**：编码被推迟到设计完成之后
- **文档驱动**：每个阶段产出文档作为下一阶段的输入

### 局限性

- 项目**末期才能见到可运行成果**
- **风险大**：错误发现晚，修改代价高
- **不适应需求变化**

### 适用场景

- 需求**稳定、明确**
- **正确性要求高**的项目

## 四、原型模型

- **核心**：快速构造一个简化的系统模型（原型）
- **特点**：快速实现、便于用户交流、逐步求精
- **适用**：不能预先确切定义需求的项目

## 五、增量模型（1980, Mills）

- **增量构造模型**：将系统分解为若干增量构件，逐个设计、实现、集成和测试
- **演化提交模型**：每个增量交付一个可运行的产品子集
- **优点**：尽早交付部分功能，降低风险

## 六、螺旋模型（Barry Boehm）

### 核心思想

- 结合**瀑布模型**和**原型模型**的迭代模型
- **强调风险分析**（风险驱动）

### 四个象限（每轮迭代）

```
① 制定计划 → ② 风险分析 → ③ 实施工程 → ④ 客户评估
```

### 风险管理三步

1. **风险识别**
2. **风险分析**
3. **风险控制**

## 七、构件集成模型（CBSD）

- **基于构件的开发**
- **5个阶段**：需求分析 → 构件分析 → 系统设计 → 开发与集成 → 测试
- **开发** = 构件组装
- **维护** = 构件升级/替换

## 八、统一过程模型（RUP）

### 二维模型

- **横轴（时间维）**：四个阶段
- **纵轴（内容维）**：六个核心工作流

### 四个阶段

| 阶段 | 核心目标 |
|------|----------|
| **初始（Inception）** | 确定项目范围和可行性 |
| **细化（Elaboration）** | 建立架构基线，消除高风险 |
| **构造（Construction）** | 开发所有构件，集成为产品 |
| **交付（Transition）** | 将产品交付给用户 |

### 六个核心工作流

1. 业务建模
2. 需求
3. 分析和设计
4. 实现
5. 测试
6. 部署

### 三大特征

- **用例驱动**
- **以架构为中心**
- **迭代和增量**
