# 第3章 软件需求分析 — 重点笔记

## 一、需求分析定义与目的

- **定义**：描写新系统的目的、范围、定义和功能
- **转化过程**：用户需求陈述 → **需求定义** → **需求规格说明**

## 二、软件需求分类

### 按层次分

| 层次 | 类型 | 说明 |
|------|------|------|
| 组织/客户层面 | **业务需求** | 组织为什么要开发这个系统 |
| 用户层面 | **用户需求** | 用户使用系统完成什么任务 |
| 产品层面 | **功能需求** | 系统必须提供的功能 |
| 产品层面 | **非功能需求** | 系统必须满足的约束和质量属性 |

### 功能需求描述要求

- **完整性**：所有功能都被描述
- **一致性**：需求之间不矛盾
- **准确性**：需求描述精确无歧义

## 三、非功能需求详解

| 类别 | 内容 |
|------|------|
| **性能** | 响应时间、吞吐量、并发用户数 |
| **外部接口** | 用户接口、硬件接口、软件接口、通讯接口 |
| **设计约束** | 技术标准、开发规范、平台限制 |
| **质量属性** | 可靠性、可用性、安全性、移植性 |

### 关键公式

- **MTBF**：平均无故障时间（Mean Time Between Failures）
- **MTTR**：平均修复时间（Mean Time To Repair）
- **可用性** = MTBF / (MTBF + MTTR)

## 四、需求分析过程

```
沟通 → 导出需求 → 可行性研究 → 精化需求 → 编写SRS → 验证需求 → 管理需求
```

## 五、利益相关者（Stakeholders）

- 用户、顾客、监管机构、系统集成商、软件团队、软件工程师

## 六、可行性研究

- **目的**：确定项目是否值得做
- **五个要素**：

| 要素 | 关注点 |
|------|--------|
| **经济可行性** | 成本效益分析 |
| **技术可行性** | 技术方案是否可行 |
| **社会可行性** | 社会环境和组织是否接受 |
| **法律可行性** | 是否符合法律法规 |
| **操作可行性** | 系统是否可操作、可运行 |

## 七、SRS（软件需求规格说明）

- 需求分析阶段的**最终产品**
- **内容**：系统数据、功能、行为、性能需求、设计约束、验收标准
- 是后续设计、实现、测试的**基准文档**

## 八、需求获取技术

| 技术 | 说明 |
|------|------|
| **会谈技术** | 非正式会谈、正式会谈、焦点小组、深入面谈、多视点分析 |
| **调查技术** | 问卷调查 |
| **场景分析技术** | 用例场景、情景分析 |
| **调研相关项目** | 研究类似系统 |
| **快速原型法** | 构建原型获取反馈 |
