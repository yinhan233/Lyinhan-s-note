# 第6章 软件设计 — 重点笔记

## 一、软件设计概念

- **本质**：把需求"变换"为构造软件的**蓝图**
- **输入** = 需求模型，**输出** = 设计模型
- **基本目标**：构造"**怎么做**"的模型
- **推迟实现原则**："设计先于编码"

## 二、设计活动

| 阶段 | 内容 |
|------|------|
| **概要设计** | 体系结构设计、接口设计、数据设计 |
| **详细设计** | 模块内部细节：算法、数据结构 |

## 三、模块化设计原理

- **模块**：独立命名的、有明确输入输出和特性的**程序实体**
- **指导思想**：分解、抽象、逐步求精、信息隐蔽、模块独立性

### 3.1 分解

- "**分而治之**"
- **复杂度关系**：C(P1+P2) > C(P1) + C(P2)
- 模块数存在**最小成本区**（过多→接口成本↑，过少→单模块复杂度↑）

### 3.2 抽象

- 抓住**主要问题**，隐藏细节

### 3.3 信息隐蔽

- 模块对其他模块**隐蔽设计决策**
- 接口**简单清晰**

## 四、模块独立性 ⭐

- 两个度量标准：**内聚**（Cohesion，块内联系）和 **耦合**（Coupling，块间联系）
- **目标：高内聚、低耦合**

### 4.1 内聚性分类（弱 → 强）

| 级别 | 说明 |
|------|------|
| **偶然性内聚** | 无关联的语句凑在一起 |
| **逻辑性内聚** | 逻辑相似的功能放一起 |
| **时间性内聚** | 同一时间段执行的操作 |
| **过程性内聚** | 按特定顺序执行 |
| **通信性内聚** | 操作同一数据集 |
| **顺序性内聚** | 前一个输出是后一个输入 |
| **功能性内聚** | 完成单一功能（**最强**） |

### 4.2 耦合性分类（弱 → 强）

| 级别 | 说明 |
|------|------|
| **非直接耦合** | 无直接关系（**最弱**） |
| **数据耦合** | 参数传递基本类型（**最弱的直接耦合**） |
| **特征耦合** | 传递数据结构 |
| **控制耦合** | 传递控制信号 |
| **外部耦合** | 共享外部数据格式/协议 |
| **公共耦合** | 共享公共数据区 |
| **内容耦合** | 直接访问内部数据（**最强**） |
