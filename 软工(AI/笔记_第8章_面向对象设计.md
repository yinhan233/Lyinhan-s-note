# 第8章 面向对象设计 — 重点笔记

## 一、设计原则

- **开闭原则（OCP）**：对**修改关闭**、对**扩展开放**
- **继承/组合复用原则**：**优先组合**，慎用继承
- **高内聚、低耦合**

## 二、OOD 概述

- 将**分析模型**转换为**设计模型**
- 补充新的类、属性、操作
- 使用设计原则和设计模式

## 三、体系结构设计

| 架构 | 说明 |
|------|------|
| **C/S** | 客户端/服务器 |
| **B/S** | 浏览器/服务器 |
| **三层架构** | 界面层 → 业务逻辑层 → 数据访问层 |
| **MVC** | Model-View-Controller |

### MVC 模式 ⭐

| 组件 | 职责 |
|------|------|
| **View** | 用户界面 |
| **Controller** | 接收请求、调度 |
| **Model** | 业务逻辑 + 数据库访问 |

- **优点**：耦合低、复用高、可维护性好

## 四、类间关系精化 ⭐

**关系强度（弱 → 强）**：

| 关系 | UML 表示 | 说明 |
|------|----------|------|
| **依赖** | 虚线箭头 | 局部变量/参数 |
| **关联** | 实线 | 成员变量 |
| **聚合** | 空心菱形 | 部分**可独立**存在 |
| **组合** | 实心菱形 | 部分**不可独立**存在 |
| **泛化** | 三角箭头实线 | 继承 |
| **实现** | 三角箭头虚线 | 接口实现 |

### 关联多重性

- **关联名**、**方向**、**角色**、**多重性**（1、0..1、*、1..*）

## 五、UML 包图

- 描述**逻辑架构**
- **包 = 子系统**
- 包之间用**依赖关系**连接

## 六、GRASP 模式 ⭐

| 模式 | 含义 |
|------|------|
| **信息专家** | 谁有信息谁负责 |
| **创建者** | 谁包含/聚集/紧密使用 A 就创建 A |
| **控制器** | UI 层之上第一个对象，协调系统操作 |
| **低耦合** | 减少类间依赖 |
| **高内聚** | 类的职责紧密相关 |

## 七、构件级设计

- 每个类**详细阐述**属性、操作、接口

## 八、构件图

- **构件 + 接口 + 依赖关系**
- **提供接口**（供他人使用）vs **需求接口**（依赖他人提供）

## 九、部署图

- **节点**（处理器/设备）+ **连接**
- **构件分配到节点**上运行
