# 第9章 软件测试 — 重点笔记

## 一、软件缺陷定义

**5 个判定规则**：
1. 未实现要求的功能
2. 出现不应出现的错误
3. 实现了未要求的功能
4. 未实现隐含的目标
5. 用户体验差（难以理解/使用）

## 二、缺陷产生原因

| 来源 | 比例 |
|------|------|
| **编制说明书** | 55% |
| **设计** | 26% |
| **编写代码** | 15% |
| **其他** | 4% |

- **越早发现，修复费用越低**

## 三、测试目标（G.J. Myers）

- 为**发现缺陷**而执行程序
- 证明软件**有缺陷**（而非无缺陷）
- 好的测试用例能**发现新错误**

## 四、测试原则

- **Pareto 法则**（80/20）：80% 的缺陷集中在 20% 的模块
- 测试**不能证明无错**
- **杀虫剂怪事**（免疫力）：重复同样的测试不再有效
- **并非所有缺陷都需修复**（考虑成本和风险）

## 五、静态测试 vs 动态测试

| 类型 | 方法 |
|------|------|
| **静态测试** | 不运行程序：桌前检查、代码会审、步行检查 |
| **动态测试** | 运行程序：黑盒测试 + 白盒测试 |

## 六、黑盒测试技术（功能测试）⭐

### 6.1 等价类划分

- 划分为**有效等价类** + **无效等价类**
- **划分原则**：
  - 范围 → 1 个有效 + 2 个无效
  - 一组值 → 每个有效 + 不允许的无效
  - 规则 → 1 个有效 + 多个无效
- **步骤**：划分编号 → 覆盖有效 → 覆盖无效

### 6.2 边界值分析

- 等价类的**补充**
- 选取**边界值**和**刚越过边界的值**

### 6.3 错误推测法

- 基于**经验**推测易出错的情况

### 6.4 因果图法

- 适用于**多输入条件相互依赖**
- **步骤**：找因果 → 画因果图 → 加约束 → 转判定表 → 设计用例

## 七、白盒测试技术（逻辑覆盖）⭐

### 7.1 逻辑覆盖法（覆盖能力：弱 → 强）

| 级别 | 要求 |
|------|------|
| **语句覆盖** | 每条语句至少执行一次 |
| **判定覆盖** | 每个判定的真/假至少一次 |
| **条件覆盖** | 每个条件的真/假至少一次 |
| **判定/条件覆盖** | 同时满足判定覆盖和条件覆盖 |
| **条件组合覆盖** | 每个判定中条件的所有真/假组合（**最强**） |

### 7.2 基本路径测试 ⭐

1. 画**程序控制流图**
2. 计算**环形复杂性** V(G)：
   - V(G) = **区域数** = **E - N + 2** = **P + 1**
   - （E=边数，N=节点数，P=判定节点数）
3. 确定**独立路径**集合（数量 = V(G)）
4. 设计测试用例

### 7.3 循环测试

| 循环类型 | 策略 |
|----------|------|
| **简单循环** | 测试 0, 1, 2, m, N-1, N, N+1 次 |
| **嵌套循环** | 从**最内层**开始 |
| **串接循环** | 各自独立测试 |

## 八、测试步骤

**单元测试 → 集成测试 → 确认测试 → 系统测试**

### 8.1 单元测试

- **驱动模块**（Driver）：模拟上级调用
- **桩模块**（Stub）：模拟下级被调用
- **任务**：接口、局部数据结构、边界条件、执行路径、错误处理

### 8.2 V 模型 ⭐

| 开发阶段 | 对应测试 |
|----------|----------|
| **需求分析** | 确认测试 |
| **概要设计** | 集成测试 |
| **详细设计** | 单元测试 |
